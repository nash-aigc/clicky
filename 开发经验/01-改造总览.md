# 01 · 改造总览

这个项目改造成现在的 `nash-aigc/clicky`，一共走过五个阶段。每一波都写清楚：**做了什么 / 为什么 / 怎么验证的**。

## 第 0 波 · 改造前是什么样

一句话：**一个必须依赖别人的服务器才能跑的演示项目**。

- 语音识别走 AssemblyAI，通过一个 **Cloudflare Worker 代理**拿临时 token。
- 视觉模型走 Claude，**API Key 写在 Xcode 的 build settings 里**（`d86c32f` 之前）。
- 语音合成走 ElevenLabs。
- 埋点走 PostHog。
- 光标是写死的蓝色三角，永远跟着鼠标，**没有任何开关**。

它对「fork 下来自己用」的人有个根本问题：**代理、密钥、埋点，全是原来那个实现自己的**。别人 clone 下来要么用不了，要么在用的时候把自己的东西上传到那个实现的账号里。

## 第 1 波 · 断掉代理，直连阿里云百炼

**做了什么**

- 删掉 AssemblyAI / ElevenLabs / Anthropic 三条接入，换成阿里云百炼（Model Studio）：
  - 识别 → `qwen3-asr-flash-realtime`，走 websocket 流式
  - 视觉 → `qwen3-vl-plus`
  - 朗读 → `qwen-audio-3.1-tts-flash`
- `worker/` 目录**保留但不再编译、不再调用**，只作参考。
- 密钥从 build settings 挪到 `leanring-buddy/BailianSecrets.plist`（gitignore），并在仓库外 `~/Library/Application Support/Clicky/` 放一份，这样 `git clean` 也冲不掉。

**为什么**

改造前的 Worker 是原来那个实现的账号，别人用就是蹭那个实现的额度；而且请求内容和密钥都要经过第三方中转。直连之后，**用户的截图和语音只到用户自己选的服务商**。

**怎么验证的**

三个模型各发一次真实请求：识别用麦克风按住说话、视觉用真实截图、朗读听一遍音频。当时是在一个 `bl model list` 确认过模型 ID 之后才写进代码的。

> 这里定下了一条一直沿用的规矩：**模型 ID 不靠记忆写，先查官方清单**。

## 第 2 波 · 换音色

**做了什么**

`de35391` 把 TTS 音色换成通过 voice-enrollment 克隆的「赵今麦」。

**为什么**

默认音色（`Cherry` 那一类）是通用女声，念长句很平。克隆音色的自然度高一个档次。

**踩到的坑**

换音色时发现 **音色名和端点族是绑死的**：`Cherry` 是 Qwen-TTS 族的名字，拿去调 Qwen-Audio-TTS 族的端点会报 `[cosyvoice:]Engine error [411]`——一个完全看不出是「你走错端点了」的错。详情见 [`04-模型接入.md`](04-模型接入.md) 和 [`10-踩过的坑.md`](10-踩过的坑.md)。

---

## 第 3 波 · 删掉 PostHog

**做了什么**

把改造前的 PostHog 埋点整个移除。

**为什么**

它上报的是：**用户的原始语音转写文本、模型的原始回答、用户的邮箱地址**。而且每一次消息都在主线程做同步磁盘写入。

对一个「帮你看屏幕、听你说话」的工具来说，这三样东西加起来就是「把用户当面说的话原样发给第三方」。

**怎么验证的**

全仓库搜 `PostHog` / `analytics`，确认没有残留的调用点。这一条后来固化成了 [`07-隐私与安全.md`](07-隐私与安全.md) 的原则。

## 第 4 波 · 设置窗口 + 可配置模型 + 对话记忆（`ee4a887`）

**做了什么**

这是最大的一波。三件事：

**1. 模型变成用户可配的。** 引入「三个角色」的概念：

| 角色 | 干什么 | 默认 |
|---|---|---|
| 👂 `transcription` | 语音转文字 | `qwen3-asr-flash-realtime` |
| 🧠 `vision` | 看截图、回答问题 | `qwen3-vl-plus` |
| 👄 `speech` | 把回答念出来 | `qwen-audio-3.1-tts-flash` + 克隆音色 |

每个角色可以指向不同的服务商。配置存在仓库外的 `~/Library/Application Support/Clicky/ModelConfiguration.json`（0600）。

**2. 一个七页的设置窗口。** 通用 / 模型 / 对话与记忆 / 听 / 说 / 看与截图 / 快捷键。侧边栏每一项后面的数字**就是那一页真实生效的设置条数**——这是有意的约束，防止有人塞一行装饰性的假设置进去。

**3. 对话记忆。** 「记住最近多少轮」「重启后保留对话」「历史自动压缩」「历史里带截图」。

**为什么**

改造前的模型和音色都是写死的，用户想换个便宜点的模型、或者换个服务商，只能改代码重新编译。对一个 macOS 小工具来说这不可接受。

**踩到的坑（都在 [`10-踩过的坑.md`](10-踩过的坑.md) 有详细版）**

- **设置窗口打不开 / 打开了打不了字**：`LSUIElement` 应用永远不是活跃应用，不先 `NSApp.activate()` 窗口就永远不是 key window，而**非 key 窗口的文本框会静默吞掉所有按键**——看起来就像表单坏了。
- **配置文件读不出来**：给 `ProviderProfile` 加一个 `Bool` 属性，合成的 `Codable` 会让所有**旧配置文件**直接解码失败。必须用 `Bool?`。
- **推理关不掉**：试了三个看起来合理的开关，只有两个真的有用。详见 [`04-模型接入.md`](04-模型接入.md)。

## 第 5 波 · 光标三档 + 形状 + 跟随距离（本次，未提交）

**做了什么**

用户的原话是：

> 「现在没法关掉这个蓝色光标，它一直显示，能不能让它可以不显示、可以隐藏。目前有一个设置是"光标闲置后自动隐藏"，但实际上它没有隐藏。」

以及：

> 「显示的位置能不能让用户调一下……因为现在相当于总有一个尾巴在跟随，体验不太好。」

于是：

- 新增三个设置：**显示方式**（一直显示 / 只在对话时出现 / 只在指位置时出现）、**形状**（三角箭头 / 标准指针）、**跟随距离**（重叠 / 紧贴 / 稍远）。
- 顺手把「光标闲置后自动隐藏」从「回答的呈现」搬到新的「蓝色光标」分组，并让它在「一直显示」档下**变灰**。
- 删掉 `isClickyCursorEnabled` 这个开关（原因见下）。

**根因（这才是这一波真正的价值）**

不是设置坏了，是**那个设置够不着**：

- `CompanionManager.isClickyCursorEnabled`（UserDefaults，默认 `true`）是唯一的开关；
- 它唯一的 UI 是菜单栏面板里的一行 "Show Clicky"，而**那一行在代码里被注释掉了**（`CompanionPanelView.swift:64-71`）；
- `scheduleTransientHideIfNeeded()` 第一行是 `guard !isClickyCursorEnabled && isOverlayVisible else { return }`。

开关永远停在 `true`，所以那段「临时唤出、用完淡出」的机制**一次都不会执行**。设置页里那个滑块，描述里写着「关闭『显示光标』时……」，而它引用的那个「显示光标」控件在界面上根本不存在。

这正好撞上项目自己定的原则：**一个能保存但什么都不做的设置，比没有这个设置更糟**。

**怎么验证的**

- 静态：`swiftc -typecheck` 零错误；`xcodebuild … build` 成功。
- 界面：写了一个**离屏渲染探针**，直接把真实的设置窗口画成 PNG 再人眼看（见 [`03-设置与配置.md`](03-设置与配置.md) 的「怎么验证界面」）。第一次渲染就发现两个问题：分段选择器的标签换行了、有一行看起来挤出了卡片。前者把标签压到 4 个字以内解决了；后者是渲染图被窗口底边裁切造成的误判，把窗口内容撑高再看就正常了。
- 运行时：需要用户在 Xcode 里 Run 之后手动过一遍（macOS **不会**给运行中的进程换代码）。

## 五波做下来沉淀下来的几条原则

| 原则 | 血的教训来自 |
|---|---|
| **不留下「能保存但不生效」的设置** | 「光标闲置后自动隐藏」够不着 |
| **能配的东西就不要写死在代码里** | 模型、音色、端点 |
| **用户的原始内容不上传到任何地方** | PostHog 那一波 |
| **数字要实测，不要凭印象** | 推理延迟、`max_tokens` 上限、TTS 成本 |
| **同一个问题试两次不成就去读官方源码** | TTS 端点族、推理开关 |
