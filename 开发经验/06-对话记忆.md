# 06 · 对话记忆

「对话与记忆」是设置窗口里的一页，六条设置。但**四条设置背后是一整套管线**，不是四个布尔值。这一篇讲那套管线。

涉及文件：`ConversationHistoryStore.swift`（207 行，唯一往磁盘写用户原话的地方）、`CompanionManager.swift` 里的记忆部分。

---

## 一、六条设置

| 设置 | 作用 |
|---|---|
| 记住最近多少轮对话 | 回放多少轮完整对话（默认 10） |
| 重启后保留对话 | **总开关**。关掉 = 不存盘，而且**删掉已有文件** |
| 历史自动压缩 | 老掉的轮次折叠成一段摘要 |
| 历史里带截图 | 回放时把当时的截图一起发回去 |
| 回答长度 | 见 [`04-模型接入.md`](04-模型接入.md) 的系统提示词部分 |
| 补充指令 | 用户自己写、排在最前面的额外要求 |
| 清空对话记忆 | **是一个动作，不是一个设置** |

---

## 二、为什么「清空对话记忆」不走草稿

设置窗口里绝大多数的改动都是**先改草稿、按保存才落盘**。清空对话记忆**刻意不走这条路**：

> 删一个文件不应该依赖于用户同时还按了「保存」。

所以它是直接执行的动作。这是那一页里唯一一个不是设置的行。

---

## 三、存什么、不存什么

`StoredConversationHistory` 里有两个字段：

```swift
var entries: [ConversationHistoryEntry]
var summary: String = ""       // 老掉的轮次压缩成的摘要
```

### 截图**不存盘**

`ConversationHistoryEntry` 里有 `userScreenshots`，但它**故意不在 `CodingKeys` 里**。所以：

- 截图在**内存**里活着，会话期间可以用；
- 一旦重启，截图就没了——**这正是那条设置的描述所承诺的**。

这不是偷懒，是有意的：磁盘上留一份「用户过去 N 次提问时屏幕上是什么」比留一份文字严重得多。

### 关掉开关要**删文件**，不只是停止写入

「重启后保留对话」关掉时，`ConversationHistory.json` 是**被删掉的**，不是留着不再更新。理由同上——用户关掉它是想让它消失，不是想让它冻结在这里。

---

## 四、回放

每一轮过去的对话都作为**真实的对话轮次**发回去，而不是塞进系统提示词里。

- 「历史里带截图」开着时，每一轮**带自己当时的截图**；
- 关着时就是纯文字；
- **从磁盘恢复的轮次永远是纯文字**（因为截图从来不落盘）。

---

## 五、自动压缩

老掉的轮次不是直接丢掉，而是**折叠成一段摘要**。

```
最近 N 轮  →  原样回放
更老的     →  压缩进 compressedHistorySummary
```

压缩本身也是一次模型调用，用的提示词是：

> you compress conversations into short notes that another assistant will read to keep helping the user. reply with the notes only.

### 摘要作为**第二条 system 消息**发送

这是这一块**最重要的一个设计决定**：

```swift
var messages = [["role": "system", "content": systemPrompt]]
if !conversationSummary.isEmpty {
    messages.append([
        "role": "system",
        "content": "summary of earlier turns in this conversation that are no longer shown in full:\n\(conversationSummary)"
    ])
}
```

**为什么不拼到第一条系统提示词后面**：摘要描述的是**过去发生过什么**，不是**指令**。一个跑偏了的摘要如果混进指令提示词里，模型会把它当成**用户提的要求**去执行。

分成两条消息，语义上就分开了。

---

## 六、什么时候这套东西**整个不跑**

「重启后保留对话」关掉时，回放、压缩、存盘——**全部跳过**。这是总开关，不是三个独立开关之一。

默认是**关**的。理由：这是唯一一条会把**用户自己说的话**写到磁盘上的设置，所以默认不能开。

---

## 七、和语音管线的交界

有两个地方和 [`05-语音管线.md`](05-语音管线.md) 交叉：

1. **回答气泡的清理要等朗读结束**，而记忆管线在后台并行地压缩老轮次——两者不要互相等。
2. **确认模式下**，转写文字不发送、也不进历史，直到用户轻点快捷键确认。

---

## 八、这一块的经验

| 经验 | 来自 |
|---|---|
| 「删掉」要真的删，不要只是停止写入 | 「重启后保留对话」关掉 |
| **摘要不是指令**，分开发 | 第二条 system 消息 |
| 敏感数据（截图）不落盘 | `CodingKeys` 里没有它 |
| 删除类操作**不要挂在保存按钮上** | 清空对话记忆 |
| 唯一会把用户原话写盘的功能，默认必须关 | 默认 `false` |
