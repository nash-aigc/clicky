## 三、循环（已有，不要改）

```
一个回合 = 看 → 决定 → 做一个动作 → 再看 → …（上限 15 步）
```

三条**由代码强制**的规矩（不是靠提示词自觉）：

1. **一步只执行第一个动作**——解析出的其余标签不执行，并在下一轮的提示里告诉模型"有几个没执行，一个个来"
2. **动作之间等 1.2 秒**再截图（页面加载要时间，连发四步会都落在没加载完的屏幕上）
3. **`[WAIT:n]`（1–10 秒）** 让模型自己等加载，而不是硬着头皮在半个页面上操作

## 四、工具怎么找：三层，但今天只用前两层

| 层 | 内容 | 何时在提示词里 |
|---|---|---|
| **L0 索引** | 每项一行：工具名 + 何时用 | **今天全部常驻**（十几条，装得下） |
| **L1 展开** | 参数、示例、怎么校验 | 命中后才展开（失败时连同错误一起回填） |
| **L2 技能内引用** | 技能正文里说"第一步用某工具" | 用到那一处才展开 |

**今天不装路由中间层**（本地短语表/JEV 都先不做）：候选只有十几条，直接给主 agent 看最快也最简单。
**超过 150 条**才升级（[00](00-从这里开始.md) §四）。

工具与技能是**并列的两种东西**，不是上下层：

| | 工具 | 技能 |
|---|---|---|
| 本质 | 函数式：有参数、有返回值、可校验 | 方法论：教"这类事怎么做" |
| 例 | 保存到 Notion、备忘录新建 | 怎么写技术文章、怎么分析竞品 |
| 谁执行 | 脚本 / 指令 / MCP | **模型自己**（读进去照做） |

细节见 [`细节/06-工具库与MCP.md`](细节/06-工具库与MCP.md)（含"该固化什么"的判据：
**要替模型记住它不可能知道的东西**——比如你的 Notion 页面 id）。

## 五、结果怎么写回来（三态协议）

每个工具/脚本的 stdout 统一吐三态（[`细节/06`](细节/06-工具库与MCP.md) §5.5）：

| 状态 | 主 agent 怎么处置 |
|---|---|
| `done_verified` | 直接报告完成（脚本自己读回验证过） |
| `done_unverified` | **主 agent 自己决定**要不要多看一眼（大多数接受） |
| `failed` | **必须回传**，带上错误原文，让主 agent 换个做法 |

**为什么不要 per-script 校验子 agent**：封闭环境里的模型没有工具，只能附和；
给它工具就是"穷版主循环"，冗余。**最便宜的校验器是主循环本身**（它有用户原话和屏幕）。

## 六、失败与升级

| 情况 | 处置 |
|---|---|
| 单步失败（点不到、找不到元素） | 回传错误 → 主 agent 换做法，继续循环（≤15 步） |
| 循环 10 轮仍未完成 | **升级 Claude Code**：打包（原话 + 已试步骤与失败原因 + 当前屏幕 + "继续完成"） |
| Claude Code 也 10 轮未完成 | **通知用户**："这件事我没做成"（[07](07-回传与通知.md)） |
