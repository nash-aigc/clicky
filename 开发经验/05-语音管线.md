# 05 · 语音管线

一条链：**按住快捷键 → 录音 → 流式识别 → 截屏 → 视觉模型 → 流式回答 → 分段合成 → 播放 → 指路 → 收尾**。

这一篇讲这条链上每一段的实现要点，以及**为什么每段都得是现在这个写法**。

涉及文件：`BuddyDictationManager.swift`、`GlobalPushToTalkShortcutMonitor.swift`、`BailianRealtimeTranscriptionProvider.swift`、`BailianTTSClient.swift`、`CompanionManager.swift`。

---

## 一、按住说话

**为什么用 `CGEvent` tap 而不是 AppKit 的全局监听**：这个 App 是后台运行的（`LSUIElement`），修饰键组合（默认 `ctrl + option`）在 AppKit 的全局 monitor 下后台检测不可靠。所以用了一个**只监听、不拦截**的 `CGEvent` tap：

```swift
CGEvent.tapCreate(..., options: .listenOnly, ...)
```

`.listenOnly` 是关键——**它不会吃掉用户的按键**，只是旁听。用 `.defaultTap` 的话会把系统里所有按键都拦下来，那是个灾难。

## 二、流式识别

`BailianRealtimeTranscriptionProvider` 走 websocket：

1. 连到 `WSS {base}/api-ws/v1/realtime?model=…`
2. 先发一个 `session.update` 配置会话
3. 把麦克风的 PCM16 音频按 **100 ms 一块**、base64 编码流上去
4. 松键时收到最终转写

### 一个共享的 `URLSession`

**整个 provider 只有一把长命的 `URLSession`**，所有会话共用（session 归 provider 所有，不归每次识别所有）。

原话是：**每次识别新建一个再 invalidate，会破坏 OS 的连接池**，连续快速重连几次之后就开始报 `Socket is not connected`。

### 值传递，不是引用

转录会话拿到的是**值**（`websocketURL` 和 `apiKey` 是普通属性），不是从 store 里现读。这样一次「保存」落在录音中途，**不可能**产出一个 host 和 model 对不上的 socket。

### `deinit` 里绝对不能 `cancel()`

这是这条链上**唯一一个会直接崩掉进程**的坑，而且症状极具误导性：

**现象**：每次最后一段转写回来之后，进程立刻 `EXC_BAD_ACCESS`，崩在 `_Block_release` 里，线程是 `stateQueue`。

**根因**：每个 provider 都把自己可变状态串行化在一条私有 `stateQueue` 上，通过 `stateQueue.async { self… }` 访问。**这个闭包会隐式持有 `self`。** 所以从 `deinit` 里调 `cancel()`，等于**去 retain 一个引用计数已经归零的对象**。等这个排队的 block 稍后被释放，多出来的那一次 release 就 over-release 了 `self`。

**修法**：`deinit` 里**只能直接给对象发消息**（比如关掉 websocket），**不能走 `stateQueue`**。所有者必须在**每一条销毁路径**上显式调 `cancel()`。

## 三、确认模式（「松开立即发送」关掉时）

默认是**松键就发**。关掉之后进入确认模式：

- 转写文字**不发送**，而是显示在光标旁边；
- **轻点一下**快捷键（按下时长 **< 0.6 秒**，`confirmationTapMaximumDurationSeconds`）才发送。

### 为什么规则是「按时长」而不是「按内容」

因为在松键的那一刻，识别服务**还没有返回这一次的最终转写**。所以「这一次用户说话了没有」**不是松键事件能回答的问题**。

按时长判定就不依赖识别结果，是一个松键事件自己能回答的问题。

### 空转写永不发送，也永不清空

这条很重要：**如果一个用户第一次按住说话没被听到，他要能再按一次而不丢掉已经说的话。**

## 四、回答文字气泡

三个设置和它有关：**回答时显示文字**、**说话时实时显示识别文字**、**回答文字多留一会儿**。

**一个气泡，显示「流式回答」和「实时转写」里当前的那个。**

### 空字符串是唯一的开关

`""` 既是「不要显示」也是「没有东西可显示」——**这两种状态是同一个状态**。所以覆盖层只需要盯一个条件。

### 「多留一会儿」等的是朗读，不是 `speakText` 返回

`scheduleAnswerBubbleClear(lingerSeconds:)` 轮询 `bailianTTSClient.isPlaying`。它在**最后一块**播完之前一直是 `true`，然后才开始用户设的「多留一会儿」。

**如果按 `speakText` 返回的时机清掉**——这正是 App 原来干的事——会怎么样？

`speakText` 在**播放开始**时就返回了。于是气泡在第一块音频合成的那一两秒里显示，然后在**用户刚开始听的那一刻消失**。

### 两个刻意的后果

**① 那一刻会把流式文字换成 `spokenText`。** 因为原始流里还带着 `[POINT:…]` 标签，而它现在要在屏幕上待好几秒。

**② 每一条接管气泡的路径都必须走 `clearAnswerBubble()`。** 否则上一次回答留下的「待清除」会在下一次**流式回答中途**触发，把开头几个字吃掉。

**③ `scheduleTransientHideIfNeeded` 也要等气泡。** 气泡是**由光标画出来的**，淡出光标会把文字一起带走。

## 五、朗读（TTS）

### 分块

`BailianTTSClient` 把回答切成**按句子对齐**的块，第一块立刻播，其余排队。这样播放从**第一块合成完**就开始了，而不是等整段。

块的字符上限是设置项 **`maximumSpeechChunkCharacters`**，默认 500。

### 成本是**线性**的（2026-09-21 实测）

`qwen-audio-3.1-tts-flash` + 克隆音色，**合成 + 下载**：

```
≈ 19 ms / 字 + 450 ms 固定开销
```

| 字数 | 耗时 |
|---|---|
| 10 | 0.72 s |
| 90 | 1.98 s |
| 250 | 5.85 s |
| 600 | 9.43 s |

**关键推论**：因为块上限是 500 字，一段正常的口头回答**就是一块**，所以用户要**等整段合成完才能听到第一个字**。

**这里没有开关可以关**（不像推理那一段）。能拉的两个杆是：

1. **回答短一点**——系统提示词里已经要求「一两句话」；
2. **长回答时，第一句先合成、剩下的边流边合。**

### 一次回答一个声音

`speakText` 在**开头快照一次**解析好的角色，所有分块都用它。如果每块现读，一次「保存」落在第 1 块和第 2 块之间，就会让同一次回答**前半句一个声音、后半句另一个**。

同理，语速和音量也是**一次快照**：一次回答应该只有一个语速。

## 六、回答末尾的位置标签

模型可以输出 `[POINT:x,y:label:screenN]`，触发光标飞过去指那个元素。解析在 `CompanionManager.parsePointingCoordinates`：

```swift
#\[POINT:(?:none|(\d+)\s*,\s*(\d+)(?::([^\]:\s][^\]:]*?))?(?::screen(\d+))?)\]\s*$#
```

三个要点：

- **只在末尾匹配**（`$`）。答案中间提到 `[POINT:...]` 不会误触发。
- **`[POINT:none]` 是合法的**，表示「这个回答不需要指」。
- **标签会从「说的话」里剥掉**，用户不会听到「POINT 860 逗号 50」。

坐标怎么换算成屏幕位置，见 [`02-光标与覆盖层.md`](02-光标与覆盖层.md)。

## 七、打断

设置项里有两个和打断有关的：

- **新提问立刻打断播报**（默认开）
- 说「打断」不是靠语音活动检测，而是靠**用户又按了一次快捷键**——按住说话本身就意味着新的一轮开始了。

## 八、这一块的经验

| 经验 | 来自 |
|---|---|
| `deinit` 里不能调会隐式 retain `self` 的东西 | `EXC_BAD_ACCESS` in `_Block_release` |
| 流式会话的 `URLSession` 要**共用一把** | `Socket is not connected` |
| 给流式会话传**值**，不要传「现读配置」的引用 | 保存落在录音中途 |
| 确认模式的判据要选**松键事件自己知道的事** | 松键时还没有最终转写 |
| 清气泡要等**播放结束**，不能等 `speakText` 返回 | 它在播放**开始**时就返回 |
| 一次回答只解析**一次**角色/语速/音量 | 否则一次回答两个声音 |
