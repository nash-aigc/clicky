# 流程图设置页

> 用户的需求（2026-09-24 深夜）：
>
> > 在设置页面增加一个"流程图"选项。用户点击之后，在右侧显示整个 agent 的工作流程，用线性图或流程图简要展示。
> > 这个图可以在右上角点击悬浮、放大，也可以直接下载到桌面，文件保存到项目文件夹的某个位置即可，方便用户理解当前软件的工作原理。
>
> 它是**面向用户的理解入口**——把本文件夹的设计翻译成一张图。状态：**设计已定，尚未实施**。

---

## 一、设置页

| 项 | 设计 |
|---|---|
| 页面 | `SettingsPage` 新增 `.workflowDiagram`，标题「流程图」 |
| 位置 | 侧边栏第一组的末尾（「Agent」下面）——它解释的是整个 agent 体系，不是某一项设置；不放「看与操作」（那组是能力闸门） |
| 页面属性 | **只读页**：没有 恢复默认/保存 行（照 `isSettingsTransferPage` 的先例，在 `GeneralSettingsActionBar` 之外） |
| 右侧内容 | 工作流程图（纵向，适配滚动），见 §二 |

## 二、图的内容（与 [`01-分流与边界.md`](主控循环Agent/01-分流与边界.md) v2 流水线一字对齐）

```
用户说话 / 打字
   ↓ 转写
【第 0 步 · 词面匹配】本地预设表（关键词 → 预先编排的代码）
   ├─ 命中 ──→ 直接执行代码 ──→ 模型只说一句收据        （零 AI 决策）
   └─ 未命中 ↓
【第 1 步 · LLM 语义匹配】能对上预设库里的哪一条？
   ├─ 对上 ──→ 执行对应预设（带模型生成的参数）
   └─ 对不上 ↓
【第 2 步 · LLM 分类】四类之一 + 产出（标签 / 参数 / 计划）
   ├─ ① 纯显示 ─→ 画圈 / 飞光标 / 画图讲解 ──→ 结束（无检查、无循环）
   ├─ ② 纯代码 ─→ 预设脚本+参数 / 现写一行（过危险词检查）→ 结束（无检查、无循环）
   ├─ ③ 组装·自由 ────┐
   └─ ④ 组装·技能引导 ┤（技能热加载描述 → 选中 → 正文引导）
                      ↓
              【循环：执行一步 → 看结果】
              完成了？──是──→ 报告结果
                 ↓否
              ≥10 轮且卡住？──────→ 继续循环
                 ↓
              30 轮到顶 ──→ 如实告知未完成 + 卡在哪
```

**两条必须如实呈现的红线**（用户这次明确要求）：①② **不需要校验、不需要检查**；③④ 每轮检查是否完成，**最少 10 轮不许放弃，最多 30 轮**，完成不了就告诉用户。

## 三、交互

| 交互 | 实现 |
|---|---|
| **悬浮放大** | 右上角一颗「放大」按钮 → 图以浮层（overlay）铺满面板，点空白或 Esc 收起——照归档页确认弹层的既有形状 |
| **下载到桌面** | 「导出」按钮 → 渲染成 PNG 写入 **`~/Desktop/Wanna/流程图-<日期>.png`**（App 自己的产物目录，见 [`主控循环Agent/05-截图与OCR.md`](主控循环Agent/05-截图与OCR.md) §三；目录不存在自动创建）。成功后提示完整路径 |
| 图的来源 | **单一真源**：仓库里的 `Wanna/Resources/WorkflowDiagram.svg`（与本文件夹的设计同步维护）；设置页直接渲染该 SVG（`NSImage` 原生支持），导出 = 位图化写盘。**不要**在 SwiftUI 里手画第二份——两份必然漂移 |

## 四、与设计文档的同步纪律

这张图是给用户看的**简版**；细节以本文件夹的文档为准。每次框架级修改（分类、循环规则、流水线步骤）必须**同步改 SVG**——把它加进"改框架要动的清单"：`01 文档` + `总体架构.html` + `WorkflowDiagram.svg` 三件一起。
