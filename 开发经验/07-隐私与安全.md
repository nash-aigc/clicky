# 07 · 隐私与安全

这个 App 的工作内容是「**看你的屏幕、听你说话**」。所以隐私不是加分项，是它能不能被信任的前提。

这一篇记录：改造前做了什么、为什么必须删、以及现在密钥和数据放在哪。

---

## 一、改造前的 PostHog 埋点——删掉的原因

改造前集成了 PostHog，上报三样东西：

| 上报内容 | 为什么不能接受 |
|---|---|
| **用户的原始语音转写文本** | 用户按住快捷键说的每一句话，逐字上传 |
| **模型的原始回答** | 模型看到了用户的屏幕之后说了什么 |
| 用户的**邮箱地址** | 直接把身份和上面两样绑在一起 |

而且它**每一次消息都在主线程做同步磁盘写入**——这既是一个性能问题，也说明了这个埋点写的时候没考虑过代价。

**三条加起来是什么**：用户对着电脑说「帮我看看这个报错」，连同屏幕上那份报错、以及这句话本身，一起发到第三方。这已经不是「匿名使用统计」了。

**处理**：整个移除。全仓库搜 `posthog` / `analytics` / `telemetry` 已经没有残留（`worker/` 目录不算，它不参与编译也不被调用）。

### 顺带修掉的另一件事

改造前还把一个 **Anthropic 的 API Key 直接写在了 Xcode 的 build settings 里**。`d86c32f` 把它删了。

**教训：密钥永远不进版本库，也不进 build settings。** build settings 是会被提交的。

## 二、密钥现在放在哪

| 位置 | 内容 | 谁读 |
|---|---|---|
| `leanring-buddy/BailianSecrets.plist` | 百炼的 Key 和 workspace URL | **不提交**（已在 `.gitignore`） |
| `~/Library/Application Support/Clicky/BailianSecrets.plist` | 同一份，仓库外 | 第一次运行时播种用 |
| `~/Library/Application Support/Clicky/ModelConfiguration.json` | 真正的真相来源 | 三个客户端，每个请求现读 |

### 为什么仓库外还要放一份

`leanring-buddy/BailianSecrets.plist` 在仓库里，所以一次 `git clean -xfd` 会把它冲掉，一次干净的 `git clone` 根本没有它。放在 `~/Library/Application Support/Clicky/` 的那份**跟着用户走，不跟着仓库走**。

`AppBundleConfiguration` 的查找顺序是：bundle Info → `Info.plist` → 打包进 bundle 的 `BailianSecrets.plist` → Application Support 里那份。所以两种情况下都能找到。

### plist 现在只是「第一次运行的种子」

第一次启动时，如果 `ModelConfiguration.json` 不存在，plist 里的 URL 和 Key 会被用来建一张「阿里云百炼」卡片，三个角色都指向它。

**之后 plist 再也不读。** 用户事后改 plist 不会有任何效果，除非先删掉 JSON。设置窗口才是被支持的修改方式。

**而且播种是纯内存的**——用户不按「保存」，什么都不会写到磁盘。

## 三、所有配置文件的权限是 `0600`

三个文件全部 `0600`：

- `ModelConfiguration.json`（里面有 Key）
- `AppSettings.json`
- `ConversationHistory.json`（里面有用户说过的话）

写法必须是**两步**：

```swift
try data.write(to: fileURL, options: .atomic)
try FileManager.default.setAttributes([.posixPermissions: 0o600], ofItemAtPath: fileURL.path)
```

**`.atomic` 写入落地时是 `0644`**（跟随 umask），所以必须在写完之后再改一次权限。只做第一步等于没做。

三个存储类（`ModelConfigurationStore` / `AppSettingsStore` / `ConversationHistoryStore`）都是这个形状——`nonisolated` + `NSLock` + 原子写 + 改权限。

## 四、什么数据会离开这台电脑

| 数据 | 去哪 | 什么时候 |
|---|---|---|
| 屏幕截图 | 用户配置的 🧠 服务商 | 每次提问 |
| 语音（PCM16） | 用户配置的 👂 服务商 | 每次按住说话 |
| 回答文字 | 用户配置的 👄 服务商 | 每次朗读 |

**没有第四个目的地。** 没有代理、没有中转、没有埋点。

这一条之所以成立，是因为第 1 波把 Cloudflare Worker 摘掉了。改造前的架构里，**所有请求都要经过原来那个实现的服务器**——那台服务器上有所有人的聊天记录和密钥。

`worker/` 目录还在仓库里，但**不编译、不调用**，只是留作参考。

## 五、密钥在代码和文档里的纪律

**密钥不出现在**：源码、build settings、README、DEPLOYMENT、提交信息、日志输出。

需要给用户示例时，一律用占位符：

```
<string>sk-your-key-here</string>
```

**多个密钥同时出现时要确认用哪一把。** 这个项目在配置过程中确实发生过「手里有几把 key，选错了哪一把」的情况。规矩是：

> **用户说要用的那一把才用。用户明确说不要用的，绝不写进任何文件。**

配置界面里，Key 的输入框用的是 `SecureField`（显示为圆点），不是普通的 `TextField`。

## 六、其余几条

**没有沙盒。** App target 不是 sandboxed。它声明的 entitlement（`network.client`、`device.camera`、`device.audio-input`、ScreenCaptureKit 的 mach-lookup 例外）都不需要 provision profile，这也是为什么 ad-hoc 签名也能编过——代价是 TCC 权限不稳定，见 [`08-构建与签名.md`](08-构建与签名.md)。

**截图不落盘。** 截出来就直接发走，`ConversationHistoryEntry` 里的截图**故意不在 `CodingKeys` 里**，所以重启即丢。见 [`06-对话记忆.md`](06-对话记忆.md)。

**覆盖层窗口按 bundle id 排除在截图之外。** 否则模型会看到光标自己。

## 七、这一块的经验

| 经验 | 来自 |
|---|---|
| **「匿名统计」里如果带着用户的原话，就不是匿名的** | PostHog 上报转写和回答 |
| **身份 + 内容 + 上下文 三样凑齐就是一次泄露** | 邮箱 + 转写 + 回答 |
| 密钥不进版本库，**也不进 build settings** | 硬编码的 Anthropic Key |
| 原子写之后**必须**再改一次权限 | `.atomic` 落地是 0644 |
| 要给别人示例时用占位符 | `sk-your-key-here` |
| 拿不准用哪把 key 时，**停下来问**，不要猜 | 配置过程中真的发生过 |
