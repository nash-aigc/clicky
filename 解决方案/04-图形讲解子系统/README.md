> 这份文档写的是**一件还没做完的事**：让 Clicky 把一副精确几何图**一笔一笔画出来**，同时**每画完一步朗读一句讲解**，像老师在黑板上边画边讲。

## 一、用户的需求（2026-09-24 定稿）

> 用动画形式演示精准图形的绘制过程，把画图做成一个动作。比如画一个三角形，先画左边一条边，再画右边一条边，最后画最右边那条边，用动画的形式呈现。同时还能语音播放，每画一个步骤播放一条语音，类似教学功能。
>
> 位置也要对：讲解类的问题（「给我讲一下这个三角形」）要把图**盖在原图上**，普通提问（「画个三角形」）要**贴着问题涉及的元素**，和屏幕无关的才画屏幕中央。

衍生需求（同日提出）：

| 需求 | 含义 |
|---|---|
| 高速 | 圈一下、指一下这类轻量交互，不能被这条重管道拖慢 |
| 音频要跟得上 | N 步讲解要能**连续播**，不能每步之间卡一秒静默 |
| 可关闭 | 一条 10–30 秒、占屏、出声的动画，用户必须能关掉、能设上限 |
| 能被打断 | 用户说「停」或直接开口，图与声音都要立刻停 |

## 二、五条核心决策（每条都有被否决的替代方案）

| # | 决策 | 为什么 | 否决了什么 |
|---|---|---|---|
| **D1** | **让几何编译器输出数据，App 不解析 SVG** | 图全部由自家 geometry-dsl 生成，它本来就知道每个图元的身份、坐标、顺序。产出 `figure.json`（元素清单 + bbox + 分步 id）比事后猜 SVG 结构可靠得多 | 否决「App 端写通用 SVG 解析器」 |
| **D2** | **一步 = 一组图元 id，揭示 = 到目前为止所有 id 的并集** | 顶层元素顺序由 `(layer, created)` 排（`svg.js:180-181`），模型一旦用 `layer`，文件顺序就与实际作图顺序脱钩；用并集则不依赖顺序，还允许同一个 id 被揭示两次（先描边、后填充） | 否决「按累计序号揭示」（现在的 `min(max(n,1), elements.count)` 就是这种） |
| **D3** | **渲染走 SwiftUI `trim` 逐笔，不上 WebView/GSAP** | ① geometry-dsl 的 path 只用 `M/L/A/Z` 四个命令（`curves.ts:60-72`），解析成本极低 ② 仓库已有「按长度比例描边」的实现（`ScreenAnnotationManager.swift:210-281`）③ 动画时钟与播报时钟都在 Swift，单一时间源 | 否决 GSAP（见下） |
| **D4** | **每步一个文本、并发合成、顺序播放** | TTS 端点不提供字级时间戳，切分单一音频需要强制对齐；而分步文本天然就是 N 段，且仓库已有并发预取的现成机制（`StreamingSpeechSession`） | 否决「合成一整段再按时间切」 |
| **D5** | **讲解放进独立 Task，与 `currentResponseTask` 同生共死** | 现在白板被动作循环每步截图前清掉（`CompanionManager.swift:2193`），且动画任务不在 `currentResponseTask` 里 → 用户说「停」取消不到它 | 否决「在动作循环里 await 整段动画」 |

### GSAP 为什么被否决（有具体证据，不是印象）

| 冲突 | 证据 | 后果 |
|---|---|---|
| 虚线 | geometry-dsl 对 `dashed=true` 输出 `stroke-dasharray`；DrawSVG **靠改写 `stroke-dasharray`/`stroke-dashoffset` 实现描边** | 两者争同一属性，虚线被吃掉 |
| 点组 `<g>` | 点标记是 `<g><circle/><text/></g>`（`svg.js:224`），DrawSVG 作用在 `<g>` 上**什么都不做** | **静默失败** |
| 多子路径 | 直角/等长标记是一条 path 里多个子路径（`svg.js:346`） | 笔尖在子路径之间跳 |
| 时钟 | WebKit 在窗口不可见时**停掉 `requestAnimationFrame`**（实测「面板隐藏时 0 帧」） | 画面停住、讲解继续 → **永久失步且无人察觉** |
| 生命周期 | `WKUserContentController` 强引用 handler，而销毁路径只做 `contentView = nil` | 每块板泄漏一组 WebKit 子进程（~88MB） |
| 观感回归 | `marker-end` 箭头会在杆没画到时先出现在终点 | 重新引入本仓库已修过的缺陷（`ScreenAnnotationManager.swift:285-288`） |

GSAP 不是永远不用——**它只在「需要任意动画/用户输入驱动的交互」时才赢**，那时再上，并把它当独立升级档（见 02 文档最后一节）。

## 四、目标架构

```
用户：「照着屏幕上这个三角形讲一下」
   ↓
视觉模型回复 [SVG_TRACE:三角形:…]        ← 讲解类不进动作循环
   ↓
AX 解析锚点元素 frame → 位置档（覆盖 / 贴边 / 中央）；找不到锚点必须如实上报
   ↓
figure_agent（独立 Task，先回一句「正在画」）
  写 .geom → 校验(≤3 轮修) → 渲染 SVG → 用渲染后的元素清单规划步骤
   ↓
产物三件套：
  图形-<stamp>.svg          给人看（不变）
  图形-<stamp>.geom         可改（不变）
  图形-<stamp>.figure.json  【新增】App 的渲染输入
   ↓
NarrationSession：并发合成 N 段讲解 → 首段就绪即开动画
   ↓
统一场景渲染器（SwiftUI）：按步揭示（id 并集）+ trim 逐笔
  每步画完 → 播该步讲解 → 播完再画下一步
   ↓
结束：按步数与时长计算淡出 → 回填 <figure_board_result>（含"已讲完"/"被打断"）
```
