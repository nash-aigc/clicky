# 04 · Agent 体系

> 这个文件夹管的是**谁在执行用户的请求**：有哪几个 agent、它们各自接收什么、边界在哪、要改什么。
> 它是「按执行体组织」的，不是「按功能组织」的——所以图形讲解、文件访问、语言适配这些**能力**都挂在
> 它们所属的那个 agent 下面，而不是各占一个顶层文档。
>
> 日期：2026-09-24 起。状态：**设计已记录，尚未实施**。

## 一、总体框架 v2：四步流水线，四类执行策略（2026-09-24 深夜重写）

> 用户的判定：旧框架按"执行体"分类是错的，正确的轴是"**这个需求本身该怎么被执行**"。
> 详细叙述与验收见 [`主控循环Agent/01-分流与边界.md`](主控循环Agent/01-分流与边界.md)。

**流水线**：第 0 步词面匹配（本地预设表，命中→零 AI 执行）→ 第 1 步 LLM 语义匹配预设库 → 第 2 步 LLM 分类（四类之一 + 产出标签/参数/计划）→ 第 3 步按类执行。

| 类 | 判据 | 检查 | 循环 |
|---|---|---|---|
| **① 纯显示** | 完成后机器状态零变化（画圈、飞光标、逐笔画图讲解） | 无 | 无 |
| **② 纯代码** | 本质是执行代码：预设脚本+参数 / 模型现写的一行（过危险词检查） | 不进观察循环；verify 由工具声明 | 无 |
| **③ 组装 · 自由** | 既非显示也非代码，AI 自己研究：用哪些工具、先后、串并行 | 看一步做一步 | **10–30 轮**（10 轮内不许报失败，30 轮到顶如实告知） |
| **④ 组装 · 技能引导** | 同 ③，但按用户预设方法论组装：技能热加载描述 → 正文引导；MCP 按官方协议 | 同 ③ | **10–30 轮** |

**Claude Code 仅两条入口**（UI 切换器 / 转写关键词 claude·cloud·cc 分流），模型**永不自主派发**——`[AGENT_SPAWN/SEND]` 解析与提示词节移除，四类流水线永远到不了它；复盘也不占四类（旁路）。**提炼通道**：高频 MCP 工具 / 用户引导型任务 → 复盘固化为脚本（→②）或技能（→④）。

## 二、真 agent 有三个（分流仍是四类）

> 如果你把画图助手、工具库也各算一个"agent"，那就是 5 个；但按"有没有自主决策的循环"这个口径，只有下面三个是。

| 执行体 | 是 agent 吗 | 为什么 |
|---|---|---|
| **主控循环**（视觉模型 + `CompanionManager`） | ✅ | 有循环、有观察（截图 + 界面结构）、有自主决策 |
| **Claude Code**（`claude -p` 子进程） | ✅ | 同上，且有自己的工具链与项目文件夹 |
| **复盘 Agent**（旁路，按时间醒） | ✅ | 读历史、自己决定固化什么、产出技能与工具——**不接用户请求**，所以它不占分流的一类 |
| 画图助手（python 脚本） | ❌ | 一次性：写 `.geom` → 校验 → 渲染 → 出图。内部虽有两处模型调用，但没有"看结果再决定"的循环 |
| 桌面管家（原 `[PY_AGENT]`） | ❌ | **本次并入主控循环**——它内部自带的模型+工具+循环被主控的循环取代，详见 [`主控循环Agent/01-分流与边界.md`](主控循环Agent/01-分流与边界.md) |
| 文件工具 / 工具库里的脚本 | ❌ | 无决策 |

## 四、三条纪律（跨全部 agent）

1. **协议记号用英文，内容跟用户语言**——标签永远英文（`CLICK`/`OPEN`），标签里的文字跟用户说话的语言。详见 [`主控循环Agent/03-语言适配与动作扩展.md`](主控循环Agent/03-语言适配与动作扩展.md)
2. **失败必须回给模型**——任何执行体的失败都要进模型的下一步上下文，否则它会以为成功了并继续说"已经做完了"
3. **一步一动作**是为了**观察**，不是保守——批处理曾经让四个动作全落在没加载完的页面上（本项目实测）。要不要放宽、怎么放宽，见 [`主控循环Agent/04-观察判据与批量.md`](主控循环Agent/04-观察判据与批量.md)
