合并桌面管家：得到了什么，砍掉了什么

  • 砍掉一层嵌套模型调用。 桌面管家不是脚本——它自带 DeepSeek 调用、三个文件工具和自己的循环（desktop_file_agent.py:176），还有第二套 key。合并后这一层整体消失
  • 文件工作变成可观察的步骤。 现在是「发一个 [PY_AGENT]，等结果」，多步要跨轮次发多个标签；合并后读→改→写→验是循环里的正常几步，每步都能看结果再决定
  • 少一个 python 依赖。 文件操作改在进程内用 FileManager，顺带少一个 key 文件、一个脚本路径的失败面
  • 少一整段系统提示词。 [PY_AGENT] 那一节的边界说明（只能在桌面、不能开 App、不能看屏幕）不再需要向模型解释
  • 保住的能力：列目录、读文件内容、写文件内容、打开文件或文件夹（[OPEN:] 今天能开 App，扩一下就能开路径）
  • 唯一要重新安放的东西：「只能碰桌面」这条隔离，从 agent 层搬到工具层——路径 realpath 之后必须以 ~/Desktop 开头，挡住 ../ 与符号链接逃逸。这一条要写测试

文件能碰哪些路径，由「逐路径授权」决定——不是「允许读写桌面」这种粗开关，见下一节。

文件访问：逐路径授权

只允许用户**显式提供**的文件夹或文件；每条路径各有「读」「写」两个开关，互不蕴含。 空列表就是一个路径都不能碰。设置页里长这样：

文件访问 允许 Clicky 读写下面这些路径，其他一律拒绝
路径读写
/Users/mjm/Desktop/项目A ✕
/Users/mjm/Desktop/项目A/notes.md ✕
/Users/mjm/Documents/资料 ✕
第一次授权后，这一页就是 Clicky 文件能力的全部范围 —— 顺序：绝对路径 → realpath → 按路径分量匹配 → 嵌套取最长匹配 → 读/写各自判定
  • 空列表 = 文件能力全关，不是默认给桌面。模型在提示词里能看到这份清单，被拒时拿到的是具体理由（哪条路径、当前允许什么），所以它不会反复试同一个路径
  • 读与写互不蕴含：只给写的条目，读也照样被拒
  • 嵌套取最长匹配：/项目A 只读、/项目A/notes.md 可写 → 写 notes.md 通过（子条目覆写父条目）
  • 四条逃逸防线：../ 越级 · 指向外部的符号链接（realpath 之后才比对）· 路径分量边界（/A 不匹配 /Ab）· 只接受绝对路径
  • 写 = 创建 / 覆盖 / 追加，不含删除。要删就单开一个删除工具与独立授权位
  • 与点击权限互相独立：可以「允许点击但禁止碰文件」，也可以反过来
