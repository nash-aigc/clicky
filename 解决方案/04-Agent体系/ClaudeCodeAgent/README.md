## 一、位置变化：从"模型可自主派发的兜底"改为"仅两条明确入口"

| | 旧（v2 之前） | **v2（本篇）** |
|---|---|---|
| 谁触发 | 模型在回复里发 `[AGENT_SPAWN]` 自主派发 | **只有两条入口**（见下），模型**永远不自主派发** |
| 提示词 | 有整节教模型怎么派发 | **该节删除**；模型不知道 Claude Code 的存在 |
| 解析器 | `[AGENT_SPAWN]`/`[AGENT_SEND]` 两个 pattern + 白名单 | **移除** |
| 定位 | 四类之外的"后台长任务兜底" | **旁路工具**：用户点名才用 |

理由（用户的原话）：它太复杂；这套 agent 是为**高频需求**设计的，Claude Code 不是日常路径。

## 二、两条入口（仅有的两条）

### 入口 1 · UI（已存在，代码事实）

点击刘海展开面板 → 左侧边栏顶部的 **「对话 / Agent / 语音聊天」切换器**（`SidebarSection.agents`，`AgentSessionManager.swift:29`）→ Agent 列表 → 选中某个 agent 对话。

这是**用户显式进入** Claude Code 的方式——面板、roster、会话记录全部照旧，一行不改。

### 入口 2.5 · 升级兜底（2026-09-25 新增，来自混合执行循环）

混合执行循环 **10 轮未完成** → 打包升级：

| 项 | 设计 |
|---|---|
| 打包内容 | 原始需求原文 + 已试步骤与失败原因（进度摘要）+ 当前屏幕状态描述 +「继续完成这个任务」 |
| 落点 | **Agent 窗口卡片**——复用/新建一个 Claude Code 会话，作为 first turn 发送 |
| 可见性 | 面板自动切到 Agent 页（照 HUD 芯片点击的既有行为）；会话状态徽章、工具调用次数、transcript 全程可见——**解决"发给 Claude 之后不知道它在干嘛"** |
| 完成后 | 现有 `announcesAgentCompletion` 语音播报；结果留在会话记录里 |
| 定位 | 这是 Claude Code 的**第三条入口**，也是唯一一条由系统自动触发的——触发条件被严格限定（10 轮 + 未完成），不破坏"日常永不使用"的原则 |

### 入口 2 · 转写关键词分流（新增，唯一需要写的代码）

```
转写完成（在发给模型之前）
   ↓
关键词匹配（大小写不敏感）：
   ├─ 「claude」或「cloud」—— 模糊匹配（语音识别的同音），含「Claude Code」「cc」
   ├─ 「cc」—— 精确匹配（词边界；过短，不做模糊）
   └─ 未命中 → 正常走主流程（第 0/1/2/3 步）
   ↓
命中 → 本轮请求整体路由给 Claude Code：
   · 用户的话原样作为任务交给当前选中的 agent（或新建）
   · 不经过视觉模型分类、不进四类流水线
   · 面板切到 Agent 页，流式回复照现有 AgentSessionView 渲染
```

| 细节 | 决定 |
|---|---|
| 匹配时机 | **转写之后、模型之前**——命中就不付视觉请求的成本（快，且不会出现"模型又把它吞了"） |
| 模糊匹配 | `claude` ≈ `cloud`（ASR 同音，用户明确要求）；正则 `cla?ud` 即可覆盖 |
| `cc` | **只做词边界精确匹配**（`/\bcc\b/`）——两个字母做模糊匹配会误伤（"execut**e**"? 不会，但"success"会）。误路由到 Claude Code 的代价大于漏路由 |
| 命中后是否还截图 | **不截**。Claude Code 不需要看屏幕（除非用户在话里明确说"看屏幕"——那是话术，原样传给它） |
| 打断/收尾 | 复用现有 Agent 子系统的中断与完成播报，不变 |

## 四、与 v2 框架的关系

| 项 | 结论 |
|---|---|
| 四类执行策略 | **不变**——它们说的是主 agent 怎么执行；Claude Code 两条入口都在四类流水线**之外**（入口 2 在第 0 步之前就分流走了） |
| "真 agent 三个" | 仍成立（主控、Claude Code、复盘），但 Claude Code 从"流水线可到的执行体"变成"旁路，仅两条入口" |
| 复盘 agent 与 Claude Code | 复盘**不**分析 Claude Code 的会话（那是另一套记录，且它太复杂不该被优化——用户的话）；复盘只看主 agent 的 turn 记录 |
| 工具库 / MCP / 技能 | 完全不受影响 |

## 五、验收

| # | 判据 |
|---|---|
| C1 | UI 入口：切换器点 Agent → 与 Claude Code 对话，行为与今天完全一致（回归） |
| C2 | 语音说「**用 Claude Code** 帮我调研 X」→ 本轮路由给 Claude Code，**没有**视觉请求（日志无 🧠 调用） |
| C3 | 语音说「**cloud** 帮我写个文档」（同音）→ 同 C2 |
| C4 | 语音说「**cc** 修一下那个项目的 bug」→ 同 C2 |
| C5 | 「success」之类含 cc 字母串的话 → **不**路由（词边界生效） |
| C6 | 「帮我调研 X」（**没有**点名 claude）→ 走正常四类流水线，**绝不**出现 Claude Code；模型也无法派发（解析器已无此标签） |
| C7 | 模型即使想派发（提示词残留场景）→ 解析器不认 `[AGENT_SPAWN]`，标签作为普通文本被念出来也不执行——**实施时确认提示词节已删，不留矛盾** |
| C8 | 命中路由时面板自动切到 Agent 页（与语音聊天 tab 的既有行为一致） |
