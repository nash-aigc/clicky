# Claude Code Agent

> 四类分流里的 **④ 兜底**：后台长任务、跨项目的工作、本机那两类都做不了的。
> 它是**真 agent**（有自己的循环、工具链和项目文件夹），但**本轮不改它**。
> 状态：**已上线；本篇只记边界与现状，作为设计时的参照**。

---

## 一、这一类是什么

| 项 | 内容 |
|---|---|
| 执行体 | `claude -p --input-format stream-json …` 子进程（`ClaudeAgentProcess.swift`），cwd 是这个 agent 的项目文件夹 |
| 接收的标签 | `[AGENT_SPAWN:name:task]`（新建或复用）、`[AGENT_SEND:name:message]`（按名字交给已有 agent，先精确匹配再包含匹配） |
| 循环 | 有——由 CLI 自己驱动，不是 Clicky 的循环 |
| 观察 | 不用屏幕。它的世界是命令行与文件 |
| 回填 | `<agent_dispatch_results>` 数据块，跟着下一次请求回去 |
| 闸门 | Agent 页的「允许 Agent 后台任务」；权限三档（只读规划 / 自动改文件 / 完全授权） |
| 上限 | 提示词限量**一篇回复最多 spawn 一个** |

## 二、它与主控循环的分工（判据）

| 需求 | 谁做 | 为什么 |
|---|---|---|
| 「帮我点一下 7」 | 主控循环 | 要动本机的界面，需要看屏幕 |
| 「把桌面 todo.txt 改一下」 | 主控循环（**合并后**） | 文件操作不需要独立 agent，见 [`../主控循环Agent/01-分流与边界.md`](../主控循环Agent/01-分流与边界.md) |
| 「帮我调研 X / 写一份文档 / 改另一个项目」 | **Claude Code** | 长任务、跨项目、要用工具链，且**不需要看屏幕** |
| 「照着这个三角形讲一下」 | 主控循环 → 画图助手 | 要在屏幕上画，属于本机的呈现 |

**判据**：需不需要看屏幕 + 是不是跨项目的长任务。

## 三、本轮不改的三条理由

1. **它不在故障里**——用户报告的"打开应用失败""抱歉"都发生在主控循环那条路上（见 [`../主控循环Agent/03-语言适配与动作扩展.md`](../主控循环Agent/03-语言适配与动作扩展.md)）
2. **它的循环不在 Clicky 手里**——改它等于改 CLI 的用法，不动 Clicky 的架构
3. **它是兜底**——兜底的价值在于"稳定、少动"

## 四、与它有交互的两个点（改动时要记得）

| 点 | 影响 |
|---|---|
| 桌面管家并入主控循环后，`[PY_AGENT]` 消失 | Claude Code 这一侧**不受影响**（它从来没收到过 `[PY_AGENT]`） |
| 真并行（见 [`../主控循环Agent/04-观察判据与批量.md`](../主控循环Agent/04-观察判据与批量.md) 第五节） | 现在提示词限量一篇回复 spawn 一个；若要提吞吐，放开到 N 个（带并发上限）是**真并行**，因为它是独立进程 |

## 五、可选的后续（不在本轮）

| 想法 | 价值 |
|---|---|
| 给 Claude Code 挂 macos-use MCP，让后台 agent 也能操作界面 | 复杂任务的 agent 获得全套界面能力。与"主控循环自己不上 MCP"不矛盾——两者是不同的执行体，各取所需 |
| 提高 spawn 上限 | 真并行地跑多个后台任务 |
| 让它的完成结果进主控的记忆 | 现在只有 `announcesAgentCompletion` 的语音播报；追问"刚才那个调研怎么样了"需要主控有记录 |
