# 02 · 数据面与渲染面——图怎么变成动画

> 这份文档回答两件事：**图的数据从哪来**（数据面）、**数据怎么变成一笔一笔的画**（渲染面）。
> 核心是决策 D1/D2/D3（见 [README](README.md)）：编译器出数据、一步一组 id、SwiftUI 逐笔。

---

## 一、数据面：桥接脚本从渲染产物提取

### 谁产出它（**这里改过一次，别再走错**）

| | 错误做法 | 正确做法 |
|---|---|---|
| 提取者 | 改 geometry-dsl 上游让它输出 JSON | **`figure_agent.py`**（Clicky 自己的桥接脚本） |
| 手法 | 手写 SVG 切分（就是现在坏掉的那个） | **Python ElementTree** 解析渲染好的 SVG |
| 为什么 | 上游是别人的子项目（自带 `.git`），Clicky 只通过 CLI 调用它 | 实测 `git -C geometry-dsl ls-files` 里**没有 `figure_agent.py`** → 该脚本未被上游追踪，可自由改；而 CLI 只有 `-o/--width/--height/--background`，**没有任何机器可读输出**，所以提取必须在渲染之后做 |

**收益**：不碰改造前 · 不需要那个手写切分器（XML 解析天然正确）· 样式属性一并拿到 · `defs`/mask/marker 在同一棵树里可解析。

### 产物：两份

```
~/Desktop/Clicky图形/
  图形-20260924-103045.svg          ← 给人看（不变）
  图形-20260924-103045.geom         ← 可改（不变）
  图形-20260924-103045.figure.json  ← 【新增】App 的渲染输入（**含 steps**）
```

**`steps` 并入 `figure.json`，不再单独维护 `.steps.json`**——两份数据两个真源必然漂移。

```json
    { "ids": [7, 11], "text": "标出直角和勾股定理" }
  ]
}
```

字段规则：

| 字段 | 规则 |
|---|---|
| `id` | 取自 SVG 的 `data-object-id`（8 种可见对象已全覆盖：`svg.js:224/260/275/280/288/292/301/306/341`）。**必须是真键**，不是数组下标 |
| `d` / `fillPath` | `d` 是描边路径；`fillPath` 是 Region 从 `<defs>` 里解出的 mask 形状。**只用 `M`/`L`/`A`/`Z`**（`curves.ts:60-72` 把平滑曲线预采样成折线） |
| `subpaths` | `d` 里 `M` 的个数。**「一个 id = 一笔」不成立**：直角/等长标记是 `paths.join(" ")`（`svg.js:346`） |
| `strokeWidth` / `fill` / `stroke` / `fontSize` / `textAnchor` | **实测必须带**：真实产物里有 `stroke-width="6"`、`font-size="28"`、`text-anchor="middle"`。漏了这些，屏幕上的图会与用户用 Preview 打开的 `.svg` 明显不同 |
| `markerEnd` | **布尔，不是 marker 引用**——渲染器自己画箭头（复用 `fillArrowheadIfComplete` 的时机逻辑），不去引用 `<defs>` |
| `transform` | 实测当前产物**没有** `transform`（`grep` 为空），但字段必须留：**非 null 就报告并降级为整图淡入**，与「未知 type」同一纪律，不许静默忽略 |
| `unsupported` | 提取时遇到渲染器还不认识的图元类型/属性，写进这个数组并在日志里报出来 |
| `steps[].ids` | 这一步揭示哪些图元。**是集合，不是累计序号** |
| `steps[].text` | 这一步要朗读的一句话（规划器产出） |

### 样式保真度：**决定跟随 App 绿调**（有意与 `.svg` 不同）

屏幕上的图用 App 的绿色描边（与绿标注同源，`ScreenAnnotationManager.swift:183`），**不是** SVG 自己的颜色。理由：图板是"悬浮在用户界面之上"的元素，和绿圈是同一套视觉语言；而且上一轮用户明确要求过"高亮绿线、无阴影、透明板"。

**代价要写在文档里**：用户用 Preview 打开的 `.svg` 与屏幕上的图**颜色不同**。这是有意为之。如果将来要"跟原色"，就是切换成 `stroke`/`fill` 字段（已经在 schema 里，改一行的事）。

### 待实测（进 [04 文档](04-验收与自检.md) 的清单）

- **`A`（弧）命令的出现频率**：若确认 `Path`/`Arc` 都以折线呈现，解析器可先不支持 `A`（遇到就降级），进一步减成本

### 规划器（`plan_steps`）的正确形态

**关键改动：移到渲染之后，喂渲染后的元素清单，而不是 `.geom` 源码。**

| | 现在 | 改成 |
|---|---|---|
| 调用时机 | 渲染前（`figure_agent.py:259`） | **渲染后** |
| 喂给模型什么 | `.geom` 源码，让它「按定义顺序编号」 | **元素清单**（`id` + `type` + `kind` + 一句话说明它是什么） |
| 要求它输出什么 | `{n: 序号, text}` | `{ids: [id...], text}`，**只准从清单里挑** |
| 校验 | `n` 是正整数、排序去重 | `ids` 全部存在于清单、并集覆盖全部元素、步数 ≤ 上限 |

这一步的意义：`n` 的语义错位**从根上消失**，因为规划器看的就是真实的图元清单，不再需要「数行号」这种必然漂移的操作。

## 二、揭示语义：并集，不是前缀

```
揭示到第 k 步 = 显示 { 第 1..k 步所有 ids 的并集 }，其余元素 opacity 0（DOM 顺序不动）
```

为什么必须是并集：

| 问题 | 前缀式（现在的写法） | 并集式 |
|---|---|---|
| `layer` 重排导致「填充先于顶点」 | 讲解顺序被文件顺序绑架 → 与老师画图顺序相反 | 讲解顺序由 `steps` 决定，与文件顺序无关 |
| 同一个 id 要「先描边、后填充」 | 做不到（`<= n` 是一次性阈值） | 天然支持：第 1 步 `[4]` 描边，第 3 步再 `[4]` 触发填充动画 |
| `<defs>` 恒占首位 | 第一步永远画空 | defs 无 `data-object-id`，由并集语义天然绕过 |
| 某些 `id` 对应零元素（`visible=false` 的辅助线消耗了 id 却不产出元素） | 出现「讲了一句什么都没动」 | 规划器的校验规则要求「每步至少命中一个真实存在且尚未揭示的元素」，命中零就并入下一步 |

## 三、渲染面：SwiftUI 逐笔

### 组件清单（约 350–450 行）

| 组件 | 做法 | 估行数 |
|---|---|---|
| `M/L/A/Z` 路径解析 | 四种命令；`A` 走 `Path.addArc` 或采样 | ~100 |
| 图元分派 | 按 `type` 走下表 | ~200 |
| Region 裁形 | 取 mask 里 `fill="white"` 的 path 做 `clipShape`（`svg.js:232-244` 结构稳定），再按并集淡入 | ~40 |
| 多子路径 | 按 `M` 拆成子路径列表，**一条一条画** | 含在上表 |
| 文字 | 遮罩从左到右揭开（或逐字，见下） | ~30 |

### 性能纪律（不然会像卡片文字那样卡）

| 纪律 | 理由 |
|---|---|
| **Path 只构建一次**，每帧只改 `trim` 进度 | 每帧重建 `Path` 是本仓库已经踩过的坑（`CardTextUnitSizeCache` 就是为这个存在的） |
| 一步的子路径**预先编号**，不在动画回调里做搜索 | 同上的原则：热路径上零分配 |
| 动画期间**不做测量**（不调 `sizeThatFits` 类的逻辑） | 测量 + 布局是 60fps 下最容易掉帧的地方 |

### 图元分派表

| type | SVG 形态 | 动画 | 注意 |
|---|---|---|---|
| `Point` | `<g><circle/><text/></g>`（`svg.js:224`） | 圆缩放弹出 + 文字淡入 | **圆与文字要分开处理**（描边 vs 淡入）；且它们同属一个 id，**永远同时出现**——不能分开讲 |
| `Line` | `<line>` | 描边（trim） | 带箭头时见下 |
| `Circle` | `<circle>` | 描边弧 / 填充淡入 | 弧从正上方顺时针扫（与绿圈一致） |
| `Arc` | `<path d="M…A…">` | 描边 | — |
| `Path` | `<path>`（可 `data-smooth`/`data-closed`） | 描边 + 填充淡入 | 平滑曲线已是 32 段折线 |
| `Text` | `<text>` | 淡入 / 遮罩揭开 | **「写出来」做不到**，见下 |
| `Mark` | 一条 path，**多子路径**（直角/等长/平行） | 逐子路径描边 | 不拆就会笔尖跳 |
| `Region` | `<rect mask="url(#g-region-N)">` + `<defs>` 里的 mask | 按 mask 裁形后填充淡入 | 元素本身是**全屏矩形**，形状在 mask 里；defs 必须在场 |
| `defs` | 箭头 marker（`fill="context-stroke"`）+ Region mask | 无动画，但**必须先于引用者存在** | 组装时不可丢 |

### 箭头时机（本仓库已修过的缺陷，别弄回去）

箭头的头必须在**杆画完之后**才出现（`ScreenAnnotationManager.swift:285-288` 的注释：「a head floating in space before the line arrives looks broken」）。SwiftUI 路线直接复用 `fillArrowheadIfComplete` 的时机逻辑；这正是 GSAP 会重新引入问题的地方。

### 文字：「写出来」做不到，两个可用替代

| 方案 | 效果 | 成本 |
|---|---|---|
| 遮罩揭开 | 文字像被从左往右「刷」出来 | 低（一个 `mask` + 宽度的动画） |
| 逐字显形 | 每个字独立淡入（教学感最强） | 中——仓库已有 `CardTextUnitBuilder` 的拆字做法可借鉴（CJK 按字、ASCII 按词） |

**诚实标注**：这是本方案最大的能力缺口，**而它恰好在讲解场景的中心**（A/B/C、a²+b²=c²、∠A+∠B+∠C 都是文字）。三家渲染方案（NSImage/GSAP/SwiftUI）**都做不到真正的"写字"**，所以它不构成选型差异，但必须在验收里明确「文字用遮罩或逐字，不作为缺陷处理」。

## 四、时间线与四个必须参数化的东西

| 参数 | 说明 |
|---|---|
| `stepDrawDuration` | 一步的描边时长（按子路径数与路径长度算，建议 0.4–1.2s） |
| `stepGapDuration` | 一步画完后、播报前的停留（默认 0，可配） |
| `tailHoldDuration` | 全部画完后保持多久（给用户读图，默认 8–15s） |
| `maxSteps` / `maxCharactersPerStep` | 上限（见 [03 文档](03-语音节拍与生命周期.md) 的时间预算） |

**单一时间源**：动画推进、播报等待、自动淡出全部由 Swift 的同一个 `Task` 驱动（`Task.sleep` + `withAnimation` + `waitUntilPlaybackFinishes`）。**不允许把动画时钟放进任何外部环境**（这是拒绝 WebView 的第一理由）。

## 五、位置三档

| 场景 | 触发 | 画在哪 |
|---|---|---|
| 讲解类 | `[SVG_TRACE:元素名:任务]`（新增标签） | **按 `bbox` 等比铺满锚点元素外框**（meet 居中，不拉伸） |
| 普通提问 | `[SVG_BOARD:元素名:任务]` | 贴元素右侧 → 放不下翻左 → 上 → 下（现有实现只有右/左，需补上下） |
| 与屏幕无关 | 同上，元素找不到时 | 屏幕中央 |

### 覆盖模式的真实难点（都已在代码里确认）

1. **SVG 没有固定 viewBox**：`examples/triangle.svg` 是 436×436，真实产物是 583×341 → 覆盖必须由 Clicky 侧按 `bbox` 反算，不能指望 SVG 自带比例。
2. **`boardSize` 目前是编译期常量** 460×360（`FigureBoardController.swift:76`）→ 覆盖模式要求它变成变量，`FigureBoardView` 的 `scaledToFit` 也要跟着改。
3. **宽高比不一致**：锚框是 4:1 的窄条而图是 1:1 时，只能 `meet`（留白）或 `slice`（裁切），**不允许拉伸**——拉伸会破坏几何图形的教学意义。
4. **放大后的线宽**：图形缩放到一个小元素上时，6pt 线可能粗到糊；建议对覆盖模式设一个最小显示尺寸（低于它就退回「贴边」档）。
5. **锚点找不到时不许撒谎**：`figureBoardAnchorFrame`（`MacosUseController.swift:1038-1053`）只搜**最前台 App 的 AX 树**；找不到时现在的退路是主屏中心 80×80 的假 frame（`CompanionManager.swift:3372-3380`），**而回填给模型的上下文却写「'三角形'旁边」**。必须改成如实上报「没找到锚点，已画在屏幕中央」。

## 六、`[SVG_TRACE:]` 要改的四处（漏一处就有症状）

| 位置 | 漏了会怎样 |
|---|---|
| 解析 pattern 列表（照 `ActionTagParser.swift:232` 的形状） | 标签完全不生效 |
| 它的 `forEachMatch` 调用（照 `:346`） | 同上 |
| **`streamingTagKeywords`（`ActionTagParser.swift:696`）** | **TTS 会把标签逐字念出来**（「方括号 S V G 下划线 T R A C E…」），而且逐句快答和光标侧气泡会一起漏 |
| system prompt 的标签清单（`CompanionManager.swift` 的 operating the computer 一段） | 模型不知道有这个标签 |

`streamingTagKeywords` 是**独立的第二份白名单**，它自己的注释就写着「a keyword added to the parser above must be added here too, or the streaming speech would read the tag aloud」。

## 七、可选升级档：GSAP 什么时候才值得上

只有当下面两条**同时**成立时才考虑：

1. 出现了固定渲染器表达不了的需求（任意时间曲线、循环/重复动画、数值驱动动画、用户输入驱动的交互动画）；
2. 下面四项**全部实测通过**：

| 必须实测项 | 判据 |
|---|---|
| `stroke-dasharray`（虚线）与 DrawSVG 共存 | 虚线图在动画中性状不变 |
| `<g>` 包裹的点组 | DrawSVG 能作用到内层 `<circle>`（或改用逐元素作用） |
| 多子路径 Mark | 笔尖不在子路径之间跳 |
| 宿主形态下的透明度与焦点 | 在 `.screenSaver + ignoresMouseEvents + 非激活进程` 的 `OverlayWindow` 里逐像素验证透明，并确认不抢 key window |

**加上两条硬约束**：① 模板**禁止使用任何浏览器音频 API**（`<audio>`/`speechSynthesis`/`AudioContext`）——会在系统里凭空多出一个音频源，与 `VoicePlaybackEngine` 的 VPIO/AEC/ducking 设计正面冲突；② handler 必须用**独立弱代理对象**并在拆除时 `removeScriptMessageHandler(forName:)`，WebView 要复用而不是每块板新建。

**过渡保险**：如果真上了 GSAP，SwiftUI 逐笔渲染器要**保留为降级路径**——WebView 加载失败时退回它，而不是「要么全有要么全无」。

## 八、同屏协调与上限（评审补出来的空白）

一条回复里可能同时出现多种"画东西"的请求，现在的代码各画各的，重叠了没人管：

| 同时出现 | 现在的行为 | 应定规则 |
|---|---|---|
| `[SHAPE:]` + `[SVG_TRACE]` | 两个独立窗口叠在同一屏，z-order 未定义 | 图板只保留一块（见下），绿标注**照画但在图板之下**（图板是主体） |
| `[POINT:]` + 图板 | 光标飞过去 + 图板同时出现，顺序未定义 | 先放图板（它是内容），再飞光标（它是指示） |
| 两个 `[SVG_TRACE]` | 上限 2，但控制器只有**一个** boardWindow → 第二块直接替换第一块 | **统一为同时只允许一块**（改 `maximumFigureBoardsPerReply = 1`，并把 prompt 的 "at most ONE" 与代码对齐） |

顺带把 `boardSize` 从编译期常量 460×360（`FigureBoardController.swift:76`）改成变量——覆盖模式已经要求它可变，同屏规则也要求按目标元素尺寸自适应。

## 九、措辞澄清（防止后来人误读）

- 本方案**否决的是「App 解析 SVG 文档结构」**（切分、找 defs、解 mask 这类），**保留的是「解析一条 path 字符串里的 `M/L/A/Z`」**——后者是 100 行的事，前者是坏掉的那个东西。
- `splitSvgTopLevelElements`（`FigureBoardController.swift:295-351`）**不是"要修"，而是**在数据面落地后**不再需要**：`figure.json` 直接给出元素清单，App 端不再做任何 XML/SVG 结构解析。落地时可以整段删掉（连同 `readSteps`），只在降级路径保留 `show()` 的 `NSImage` 一次性显示。
