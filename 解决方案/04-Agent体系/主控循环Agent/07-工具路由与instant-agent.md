# 07 · 工具路由：移植 instant-agent 的架构

> 用户的问题：
>
> > 关于 JEV 的用法，和 agent 整体架构，是不是可以完全移植过来。尤其是未来工具几百个的时候，JEV 能快速选择，减少费用消耗……这个 agent 的设计架构非常强，可能比现在的方案还要强，但是当前的方案的 MCP 和技能，是值得保留的。
>
> 结论：**架构整体移植（它和 06 的工具库本来就是同一个形状）；JEV 本身不移植——instant-agent 已经用实测把它删掉了**，它的位置被一次 DeepSeek 闭集分类调用取代。JEV 只在目录真正长到几百条时才重新入场。
>
> 状态：**设计已定，尚未实施**。所有数字引自 `instant-agent/README.md`（本机实测，非估算）。

---

## 一、先对齐事实：这两个项目是同一个形状

把 `instant-agent` 的五层和 06 的工具库并排放：

| instant-agent | 06 工具库（现状设计） | 关系 |
|---|---|---|
| `catalog.json`（id / label / params / command / verify / examples） | `manifest.json`（name / when / params / run / verify） | **同一个东西**，字段互补 |
| L0 短语表（正则 + 别名，2ms，零模型） | `aliases` 字段（对上口语说法） | 06 的 aliases 是数据，instant-agent 的 L0 是**执行引擎**——差的就是这一层 |
| L1 闭集分类（模型只选 id，不生成命令） | `[RUN:工具名:参数]`（模型挑工具 + 填参数） | **同一条规则**：模型只做选择，永远不生成命令 |
| L2 槽位校验（类型/范围/前缀，不过就拒） | 参数校验（存在，但没定义 schema 硬度） | 06 需要补强 |
| L3 执行（命令是常量，`{slot}` 是唯一可变部分） | 脚本 + 参数 | 06 需要补强：**脚本命令本身也该是常量** |
| L4 回读验证（catalog 声明了 verify 才跑） | `verify` 字段 + 失败回落 | **已经一致** |
| 拒绝优于选错（误接 0 是唯一致命指标） | 未明确 | **要移植的最重要的思想** |
| 重试 ≠ 兜底（同路径重发保留，降级路径全删） | 失败回落到手动路径 | **有张力**，见 §四 |

所以"能不能移植"的答案是：**不是移植，是合并**——06 的 manifest 升级成 instant-agent 的 catalog 硬度，再把 L0 短语表和"拒绝优于选错"两条纪律加进来。

## 二、移植清单（按价值排序）

### ① 模型只做选择，永远不生成命令（稳定性最大来源）

| 现状 | 移植后 |
|---|---|
| `[RUN:保存到Notion:内容]`——模型挑工具 + 填参数，脚本自己写 | **不变**，但 manifest 的每个工具必须声明 `params` 为**可校验 schema**（type / min / max / max_len / prefix），**校验不过就拒绝**，不做模糊补救 |

instant-agent 的实测依据：没有任意 shell，就没有"模型写错命令"这个失败模式；L2 因此能**真的挡住东西**。

### ② 拒绝优于选错（不对称判据）

> 拒绝用户看得见，选错用户看不见。误接一条都不能有，漏接可以容忍。

落到 06：`[RUN:]` 选不到工具时，**如实报告"目录里没有这个工具"**，不做相似度匹配、不挑一个"差不多"的。工具库里没有的能力，就是没有——让用户去加，或者让模型走通用路径（点击/循环）。

**与 06 的"失败回落"不冲突**：回落是**校验失败**（工具跑了但结果不对）时退回手动路径；拒绝是**选不到工具**——两条不同的失败，处置不同。

### ③ L0 短语表：高频短语零模型零网络

| 项 | 设计 |
|---|---|
| 是什么 | 一张**本地正则 + 别名表**：精确命中就直接执行，**2ms，不调模型** |
| 放什么 | 只有最高频、无歧义的短语：「打开计算器」「调音量到 50」「几点了」 |
| 判据 | 命中 = 唯一工具 + 全部槽位可从话里直接填出；**有一个槽位填不出就不算命中**（那类需求交给主控循环正常走） |
| 与现有链的关系 | 它在 `[RUN:]` **之前**：命中 → 直接执行；未命中 → 主控循环照常（模型看到 L0 索引，决定走不走 `[RUN:]`） |
| 维护 | 表就是 manifest 里 `examples` 的精确子集——**改数据不改逻辑** |

**这是"光速"的真正形态**：高频需求连那次 445–1150ms 的分类调用都省了。

### ④ `verified_at` 硬门禁 + `examples` 准确率杠杆

| 字段 | 规则 | 依据 |
|---|---|---|
| `verified_at` | **null = 目录里但没端到端跑过 → 执行时警告**（或不执行） | instant-agent 把它从"标记"升级成"硬门禁" |
| `examples` | 每个工具 2–5 条口语示例。**遇到漏接，先加示例，别改提示词** | 实测：`open_app` 不带示例时「打开系统设置」被判 no_match；带示例后同类需求正确命中 |

### ⑤ 重试 ≠ 兜底

| | 定义 | 处置 |
|---|---|---|
| **兜底** | 失败后**换一条降级路径** | 工具执行**不做**（那是 Claude Code 或手动路径的事，见 §四） |
| **重试** | 失败后**同一条路径原样再发** | **保留**——实测 `显示桌面` 首次返回非法 JSON、重发 5 次全对，那是采样抖动不是能力不足 |

## 三、规模增长路径：工具到几百个时怎么办（你问的核心）

关键数字（instant-agent 实测）：**目录 33 条全量入 prompt ≈ 3860 字符 ≈ 1.5k token；上限大约 150 条**——超过它，全量注入的开销就开始伤，需要换路由。

| 阶段 | 工具数 | 做法 | 每次请求的固定开销 |
|---|---|---|---|
| **现在** | ≤40 | L0 索引全量注入（06 现设计） | ~1.2 KB |
| **中期** | 40–150 | 仍全量注入，但按分类折叠；`[INDEX:分类]` 按需展开 | 1.2–4 KB |
| **后期** | >150 | **闭集路由**：主提示词只带分类目录（十几行），命中类目后用**一次小的分类调用**（DeepSeek，thinking 关闭）在该类目内选工具 | 主提示词 ~1 KB + 一次 450–1150ms 调用 |
| **更大** | 数百+ | 这才是 **JEV 的位置**：单次 255 上限 → **并行分片**（所有片无条件同时发，延迟 = max(片) ≈ 一次往返；多片选中不一致 → 天然拒识） | 按次计费，1 题 $0.0000142 |

**所以"JEV 能在几百个工具时快速选择、减少费用"是对的——但那是第四阶段的事**。在 ≤150 条时，一次 DeepSeek 闭集分类（445–1150ms、cache-hit 下成本可忽略）已经够用，而它**少一个外部依赖、少一个网络跳点、少一套 API 契约**。instant-agent 删 JEV 的理由不是它慢，是它带来的复杂度（255 上限 → 分块/分片/仲裁）在目录小的时侯不存在。

**触发点写死**：L0 索引注入超过 **6 KB** 或工具超过 **150 个**，就升级到闭集路由。到数百条再评估 JEV。

## 四、一处真正的张力：instant-agent "无兜底" vs 06 "失败回落手动路径"

两者说的不是同一件事，但必须写清楚：

| | instant-agent | 06 工具库 |
|---|---|---|
| 场景 | **执行期**：一个请求进来，要么命中要么拒绝 | **任务期**：一条链跑到一半失败了 |
| 它删的兜底 | 换模型 / 换目录 / 换技能的**降级路径**（引入第二条不确定路径） | — |
| 06 的回落 | — | 工具跑了但**校验不符** → 退回手动一步步做 |

**裁定**：执行期采纳 instant-agent 的纪律（**选不到就拒绝，不换路径**）；任务期保留 06 的回落（**校验失败退回手动**）——因为那不是"换一条不确定的路"，是退回**已经验证过的通用能力**（主控循环本来就是兜底）。同时工具执行加**重试一次**（同路径原样重发）。

## 五、MCP 与技能：保留，且位置更清楚了（你的判断正确）

| 资产 | 保留方式 | 在新架构里的位置 |
|---|---|---|
| **技能** | 保留（L0 索引一行 + 按需展开方法论正文） | 技能命中靠**主控**判断（它看得见对话上下文），不走 L0 短语表——技能的触发是语义的，不是短语的 |
| **MCP** | 保留，但继续**不直灌**（06 §八） | MCP 的工具要进主控循环，必须**先固化成 catalog 条目**（带 params schema + verify + examples）——**MCP 是工具的来源，不是工具的形态** |
| **工具库** | 升级成 catalog 硬度 | 见 §二 |

## 六、代码落点

| 文件 | 改什么 |
|---|---|
| `tools/manifest.json` | 条目升级：`params` 加 type/min/max/max_len/prefix；`command` 常量化（`{slot}` 唯一可变，字符串槽位 `shlex.quote`）；`verified_at` / `verify` / `examples` 必填（新建工具时） |
| 新增 | L0 短语表引擎（正则 + 别名 + 槽位抽取，纯本地）；挂在 `[RUN:]` 解析之前 |
| `MacosUseController`（或新的运行时） | L2 槽位校验（不过就拒）；重试一次；`verified_at` 门禁 |
| `CompanionManager.swift` | 系统提示词：加"目录里没有的能力就是没有"一句（拒绝优于选错） |
| 无 | **不引入 JEV**（触发点见 §三） |

## 七、验收

| # | 判据 |
|---|---|
| J1 | L0 命中一条高频短语 → **端到端 ≤ 50ms**（日志有时间戳），零模型调用 |
| J2 | L0 的槽位填不出 → **不命中**，正常走主控循环（不是报错） |
| J3 | 槽位校验失败（超出 min/max、超长）→ **拒绝**，返回具体哪个参数不合法 |
| J4 | 模型选了一个不存在的工具 id → **拒绝**，不做模糊匹配；提示词里能看到目录清单 |
| J5 | `verified_at == null` 的工具被执行 → 日志有警告 |
| J6 | 采样抖动（首次非法输出）→ 重试一次成功，**没有**走降级路径 |
| J7 | 校验失败 → 仍走 06 的回落（手动路径），两者不冲突 |
| J8 | 工具库 `grep` 不到任何内嵌命令模板之外的可变 shell——`command` 只有 `{slot}` 可变 |
| J9 | 工具数/索引体积有监控：超过 150 条或 6 KB 时日志提醒升级路由 |

## 八、诚实标注

- instant-agent 的数字（2ms / 445–1150ms / 误接 0 / 33 条 1.5k token）**全部引自它的 README，是那个项目的本机实测**；移植到 Clicky 后 L0 的 2ms 会变成"Swift 正则"，量级不变但数字要重测
- 「上限大约 150 条」是 instant-agent 作者的经验值，**不是硬测量**——所以触发点写成"6 KB 或 150 条先到为准"，且 J9 要求监控
- JEV 的数字（178ms 中位、$0.0000142/题、255 上限）引自其手册与本机旧记录，**本轮不实施，仅在目录破 150 后重新评估**
