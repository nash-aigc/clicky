# 03 · 触发与日志导出

> 这份文档回答三个问题：
> ① 复盘 agent **什么时候执行**，由谁触发
> ② 要不要 hooks（Claude Code 那种）
> ③ 会话记录怎么导出到用户的 Obsidian 文件夹——切分、增量、去重
>
> 状态：**设计已定，尚未实施**。

---

## 一、先分清两个动作：导出是廉价的，复盘是昂贵的

用户的原话：

> 如果每个任务结束之后都进行复盘，其实很不好……有一个自动化代码，在执行完成之后，把重要的、对复盘有帮助的内容保存到我提供的一个文件夹里。然后我可以让 agent 手动复盘，由我去触发它复盘，也可以在设置页面设置自动触发还是手动触发。默认是手动复盘。

**这条把两件事分开了，这是整篇设计的支点**：

| | **导出**（写会话记录） | **复盘**（调模型做总结） |
|---|---|---|
| 成本 | 写一个文件，**纯本地，零模型调用** | 一次（或多次）模型调用 |
| 频率 | 每轮结束都可以做 | 一天一次，或用户手动 |
| 默认 | **自动** | **手动** |
| 谁来触发 | turn 结束时的一个调用 | 用户点按钮 / 定时器 |

**所以"每轮都跑 AI 太贵"这个担心，靠把复盘从每轮里摘出去解决**——不是靠限制导出的频率。

## 二、不需要 hooks——Clicky 拥有自己的生命周期

你问的是不是要学 Claude Code 那种 hooks。**不用，而且在这个项目里 hooks 是个错的概念**：

| | Claude Code hooks | Clicky |
|---|---|---|
| 为什么需要 | Claude Code 是别人的程序，你只能**从外面挂**上去 | **这是你自己的程序**——turn 结束时你就在那个函数里 |
| 代价 | 一个外部进程 + 一套配置格式 + 超时语义 | 一次函数调用 |

**代码事实**：turn 结束时，主控已经在写 turn 记录（`ConversationHistoryEntry`：`progressSteps` / `turnDurationSeconds` / `turnFinishedAt` / `wasInterrupted`）。导出与触发只是**在那之后加一次调用**。

**未来如果你还要别的"挂载点"，正确做法是事件，不是 hooks**：本项目已经在用 NotificationCenter 做跨子系统通知（`.clickySessionsDidChange`、`.clickyAppSettingsChanged`、`.clickyModelConfigurationChanged`）。新增挂载点就照这个惯例——**在生命周期点上发一个通知，谁关心谁订阅**。比如：

```
.clickyTurnDidFinish  ← 未来任何"轮次结束后要做事"的需求都挂这里
```

这比 hooks 好在：进程内、无超时、无配置格式、类型安全、可单元测试。

## 三、复盘 agent 的定义，也放进用户那个文件夹

用户问"是不是应该在我给你的这个文件夹里都写上这个 agent"——**该写，但只写该写的那部分**：

| 内容 | 放哪 | 为什么 |
|---|---|---|
| **它是什么**：系统提示词、它能做什么/不能做什么、它的判据 | 用户文件夹里的一份 md（`自我升级（复盘）/agent.md`） | 用户能看见这个 agent 到底是干什么的、能自己改它的行为 |
| **模型与密钥** | 照旧 `Application Support/Clicky/` 的 0600 文件 | 密钥不进用户天天翻的文件夹，也不进 git |

## 四、会话记录导出到 Obsidian

### 四.1 目录

```
<导出根目录>/                          ← 用户在设置里指定（你的 Obsidian 库里的某个文件夹）
└── Clicky 会话记录/
    ├── 2026-09/
    │   ├── 2026-09-24.md
    │   ├── 2026-09-24-2.md            ← 同一天超过大小上限时的第二份
    │   └── 2026-09-25.md
    └── 2026-10/
        └── 2026-10-01.md
```

### 四.2 切分：**先按月分文件夹、再按天一个文件，单文件超限再切序号**

你问"按日期还是按大小"——**两个都要，它们解决的是不同问题**：

| 维度 | 解决什么 | 不做的后果 |
|---|---|---|
| **按月分文件夹** | 目录项数量 | 一年后一个目录里躺着 365 个文件，翻不动 |
| **按天一个文件** | "我想看上周三做了什么" | 一个月一个大文件，Obsidian 打开就卡 |
| **单文件超 ~500 KB 再切 `-2`** | 高频那天的单文件失控 | 一天跑几百轮时，一个 md 几十 MB |

### 四.3 增量与去重：**用水位，只追加，不重写**

你担心的"文件夹同名或内容相同"——**根源是"每次都想重写整份记录"**。改成水位就自然没有了：

```
每个 turn 有一个 exportedAt 戳（或一个全局导出水位 = 最后一条已导出的 turn 时间）
   ↓
每次导出：只取 exportedAt == nil 的 turn，**按时间升序追加**到当天文件末尾
   ↓
同一个 turn 永远不会被写两次 → **同名/重复内容在结构上不可能发生**
```

**这与复盘的水位是同一个机制**（`reviewedAt`）——两者独立、可分别推进：

| 戳 | 谁打 | 推进条件 |
|---|---|---|
| `exportedAt` | 导出器 | 写进文件成功之后 |
| `reviewedAt` | 复盘 | **整批复盘完**之后（见 [`README.md`](README.md) §六） |

**必须是追加（append），不是重写（rewrite）**：追加天然增量、天然快、天然不覆盖用户可能在 Obsidian 里做的批注。若当天文件已被用户手动改过，也不影响——我们只是往后接一段。

### 四.4 写什么（两档，可配）

| 档位 | 内容 |
|---|---|
| **精简**（默认） | 时间 · 用户说了什么（截断到一行）· 执行了什么（`progressSteps` 每步一行）· 成功/失败 · 任务标签 |
| **完整** | 加上模型回复全文、涉及的截图**路径**（不复制图片本身） |

精简档的形态：

```markdown
## 14:03 · 写代码 / 调试
- 用户：帮我把这个函数的空指针处理一下
- 执行：读取 src/a.py（成功）→ 定位空指针（成功）→ 写入修复（成功）
- 结果：成功 · 耗时 42s
```

## 五、复盘页：左列最顶部加一个「全局」

用户的要求：

> 必须在复盘按钮点击之后，在左侧边栏的最顶部增加一个全局栏。它看到的是我提供的这个文件夹里的所有文件夹，既能看历史记录，也能看复盘过程，能翻到每一个东西。它的可读权限要更大一点，这样就能有一个全局视角。

| 项 | 设计 |
|---|---|
| 位置 | 复盘页左列的**最顶部**，在三张等级卡片之上 |
| 名字 | 「全局」 |
| 内容 | 浏览**导出根目录**下的所有内容：按月的文件夹、按天的记录文件、以及复盘产出的审批文件 |
| 权限 | **比主控更大**：这是复盘 agent 自己的只读范围（用户指定的导出目录），**不是**主控那份逐路径授权清单 |
| 用途 | ① 翻历史记录 ② 关闭自动复盘时，**在这里跟它聊，它读得到历史，当场做复盘** |

**两套授权不混**（重要）：

| 谁 | 能读什么 | 依据 |
|---|---|---|
| **主控循环** | 用户在「文件访问」列表里逐条授权的路径 | [`../主控循环Agent/02-文件访问授权.md`](../主控循环Agent/02-文件访问授权.md) |
| **复盘 agent** | 导出根目录 + 审批目录（只读，且这两个目录是用户自己指定的） | 本篇 |

## 六、设置 → 复盘（增补项）

| 项 | 形态 | 默认 |
|---|---|---|
| 复盘触发 | **手动 / 自动**（分段控件） | **手动** |
| （自动时）复盘时间 | 时间选择器 | 03:00 |
| **导出会话记录** | 开关 | **开** |
| 导出根目录 | 路径 + 「选择文件夹」 | 空（未设置 → 导出关闭并说明） |
| 导出详细程度 | 精简 / 完整 | 精简 |
| 单文件上限 | 数字（KB） | 500 |

（其余项见 [`02-界面与审批.md`](02-界面与审批.md) §八。）

## 七、验收

| # | 判据 |
|---|---|
| X1 | **导出与复盘分离**：一轮对话结束后，导出发生（文件里多了一段），但**没有发生任何模型调用**（日志可验证） |
| X2 | **默认手动**：新装/恢复默认后，复盘触发是「手动」，不会自己跑 |
| X3 | **幂等/去重**：同一批 turn 连续导出两次 → 文件内容不变（第二次没有新增段） |
| X4 | **增量**：第 5 轮之后导出，文件里只多第 5 轮那一段，前四段原样 |
| X5 | **切分**：跨天写进不同文件；单文件超上限时自动生成 `-2`；跨月进新文件夹 |
| X6 | **不重写**：模拟用户手动在 Obsidian 里改了当天文件 → 下一次导出仍只往后追加，用户的修改还在 |
| X7 | **全局栏**：复盘页左列顶部有「全局」，能列出导出根目录下的所有月份文件夹与记录文件 |
| X8 | **权限隔离**：全局栏能读导出目录；主控读了同一个目录会因为**不在授权清单里**而被拒（两套授权没混） |
| X9 | 导出根目录未设置 → 导出关闭，且设置页**明确说明**（不是静静地不写） |
| X10 | 导出目录不存在 → 自动创建；不可写 → 明确报错 |
| X11 | 未引入任何 hooks 概念：全链路是**进程内调用 + NotificationCenter**（代码 review 可验证） |
