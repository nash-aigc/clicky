# 复盘 Agent（第五个执行体，旁路）

> 这份文档定的是一个**不接收用户请求**的执行体：它按时间自己醒过来，读历史，把"用户反复做但没固化的事"
> 变成技能、工具、参考条目——**快、准、有兜底**的第三块拼图。
>
> **界面与审批**（入口在侧栏底部、三张等级卡片、审批目录）见 [`02-界面与审批.md`](02-界面与审批.md)。
>
> 状态：**设计已定，尚未实施**。

---

## 一、它是什么：链条最末端的兜底 + 学习层

**框架 2026-09-25 收敛为（纯文本 / 纯视觉 / 混合执行）之后，复盘的位置**：混合执行 10 轮未完成 → Claude Code 接手 → Claude Code 结束后，复盘是它后面的兜底；同时**每一个任务（纯视觉或混合执行）结束时都打标记计数，累计 50 个自动触发**。它是学习层，不是执行层。

| | 纯视觉 / 混合执行 | 复盘 Agent |
|---|---|---|
| 触发 | 用户说话/打字 | **手动 / 50 任务计数 / 定时** |
| 输入 | 用户请求 + 屏幕 | **已完成的对话记录**（只读） |
| 输出 | 眼前的动作 | **只有文本建议**（写进指定子文件夹，批准后才生效） |
| 工具 | 全部 | **仅两个**：AnySearch（搜索）+ 写入（锁死在指定子文件夹） |

**四类分类不变**——那是"用户请求怎么执行"。复盘是旁路，所以真 agent 从 **2 个变 3 个**（主控循环、Claude Code、复盘）。

## 二、为什么需要

用户的原话：

> 某个行为用户一直在使用，但没有固化，通过复盘就可以把这个工具、路径或方法固化下来，固化成一条命令，写进知识库或参考文件里，让未来 AI 识别到相关词语时自动优化。
> 比如用户经常做一件事，本来可以通过一段代码实现，但因为没做过，所以采用一步两步三步、看一步做一步的方法，做完之后其实可以通过应用代理来实现。

**典型产出场景**：用户连续 8 轮都在"手动把内容搬到 Notion 的同一个页面"——今天靠点击一处处做，复盘看出这是一个可固化的动作 → 产出 `tools/Notion/notion_save.py` + manifest 条目 → 下次一句话完成。

## 三、输入：**不用另建日志**（先解决你最担心的那个问题）

你担心"边做边写慢、做完再写谁监控"——**这个日志已经存在了**：

| 复盘需要什么 | turn 记录里已有的字段 |
|---|---|
| 用户说了什么、它答了什么 | `userTranscript` / `assistantResponse` |
| 做了哪些步骤 | `progressSteps`（每一步的执行描述，含失败原因） |
| 花了多久 | `turnDurationSeconds` |
| 什么时候结束的 | `turnFinishedAt` ← **这就是时间水位** |
| 是不是被打断了 | `wasInterrupted` |
| 会不会把旧格式误当示范 | `recordedWithActionTags` |

（`ConversationHistoryStore.swift` 的 `ConversationHistoryEntry`。）

**所以不用新增日志系统**：turn 记录本来就是**每轮结束时写一次**——不边做边写、也不慢。复盘只读它。

只缺两个新字段：

| 字段 | 用途 |
|---|---|
| `taskLabels: [String]?` | 这轮是什么任务（见 §五） |
| `reviewedAt: Date?` | 被复盘过的时间 → **防重复**（见 §六） |

两者都按本仓库规则 E1：`decodeIfPresent`，缺省 nil，旧文件照常解码。

## 四、会话切分：单位是 turn，不是 session（解决你的两难）

你的两难：**连续会话** → 复盘时上下文混在一起；**每个任务新建会话** → 刘海面板会堆几百上千条。

正解：**切分单位是 turn，不是 session。**

| | session | **turn** |
|---|---|---|
| 是什么 | 对话的容器（面板上那一行） | 一问一答 |
| 有没有时间戳 | 有（`updatedAt`） | **有（`turnFinishedAt`）** |
| 够不够切分任务 | 不够（一个会话里混着好几件事） | **够**——每轮自带时间、步骤、长度 |

**于是不需要为切分任务而新建会话**：面板保持连续会话（体验不变），复盘读的是 **turn 流**并按标签+时间分组。你说的"第七轮和第九轮是两件事"，用两个 turn 各自的标签表达即可。

## 五、任务标签：谁打、几个、存哪

| 问题 | 答案 |
|---|---|
| 谁打 | **主控的视觉模型在每轮回复里输出**，与现有标签同一个出口：`[TASK:写代码,调试]` |
| 几个 | **1–3 个**，来自一份**受控词表**（`task_labels.json`） |
| 为什么受控 | 自由发挥会让标签发散（"写文章"/"写作"/"撰写文案"），复盘时聚不起来，等于没打 |
| 模型想用词表外的标签 | 降级为「未分类」；复盘 agent 可以**提议扩表**（进待审区，用户批准才生效） |
| 模型没打标签 | **不阻塞**——复盘 agent 退化为按 `progressSteps` + 文本聚类归类 |
| 成本 | 一行、几十字节 |
| 存哪 | turn 记录的 `taskLabels` |

## 六、触发与水位（你问的"什么时间看、看多少、怎么保证不重复"）

**触发、导出与 hooks 的完整设计在 [`03-触发与日志导出.md`](03-触发与日志导出.md)**：导出（廉价、默认自动）与复盘（昂贵、**默认手动**）是两件事；触发用**进程内调用 + NotificationCenter**，不引入 hooks。

水位本身的规则：

| 问题 | 答案 |
|---|---|
| **什么时候看** | 三种触发：① **手动**（默认——用户点复盘按钮）；② **计数自动**——连续对话中每次任务执行结束打一个标记做增量计数，**累计 50 个用户任务自动触发**（原设想 100，按 50 走）；③ 可选定时（每天 03:00） |
| **一次看多少** | 一轮最多 N 个 turn（默认 50）+ token 上限；**超限就停，水位只推到已完成的那一轮** |
| **怎么不重复** | **`reviewedAt` 逐个打在 turn 上**（主）+ 全局水位（辅）。只处理 `reviewedAt == nil` 的 |
| **正在聊的那轮** | 只处理 `turnFinishedAt < now − 冷却`（默认 10 分钟）的 turn → 进行中的对话永远不进复盘 |
| **你举的例子**（1 点复盘，7 点用户又聊了，9 点再复盘） | 1 点那批已打 `reviewedAt`；9 点只看 `reviewedAt == nil` 的 → 恰好就是 7–9 点那批。**不需要"时间轴对齐"，水位天然解决** |
| **中途崩了/关机** | 水位只在**整批处理完**后推进；`reviewedAt` 是逐个打的 → 崩了不重复、也不漏 |
| **同一批里会话交错** | 按 turn 的 `turnFinishedAt` 排序处理，标签只是分组维度，不要求同一会话连续 |

## 七、它产出什么（四类，全部进审批目录）

复盘的**三个关注清单**（v2 框架，见 [`../主控循环Agent/01-分流与边界.md`](../主控循环Agent/01-分流与边界.md) §五）：

| 清单 | 看什么 | 产出 |
|---|---|---|
| **A · 高频纯代码操作** | 哪些 `[RUN:]` / 现写代码反复出现 | 合并、参数化、进预设表 → 第 0/1 步命中率↑，更多请求零 AI |
| **B · 高频组装需求** | 自由组装（③）的需求按类型聚类：哪几类任务总在拼同样几步 | 沉淀成**技能**（下次走④）或**脚本组合**（→②） |
| **C · 反复失败 / 用户引导型** | 没有对应能力、调用多次失败、靠用户一步步引导完成的任务 | **重点对象**：梳理成脚本（→②）或技能（→④，把"怎么被引导"写成方法论）——"用户教过 AI 一次"是最强的固化信号 |

产出物仍分四类，全部进审批目录：

| 产出 | 批准后进哪 | 例 |
|---|---|---|
| **技能**（md，方法论） | `skills/` | 「技术文章写法」；「某类组装任务的步骤序列」 |
| **工具**（脚本 + manifest 条目） | `tools/` | 「保存到固定 Notion 页」；高频 MCP 工具的提炼版（→ 纯代码） |
| **参考条目**（**带关键词触发**） | `references/` | 「用户偏好：中文回复、不要 emoji」；关键词命中时随 L0 索引一起注入 |
| **建议**（不改任何东西） | （只能标记已采纳） | 「系统提示词这一段可以删」「这个工具的参数经常写错」 |

**技能与工具是并列的两种东西**（方法论 vs 函数式），不是上下层——见 [`../主控循环Agent/06-工具库与MCP.md`](../主控循环Agent/06-工具库与MCP.md) 第五节。

## 八、权限：只能新增与追加，禁止删除与覆盖

你说的"必须非常谨慎，因为它处于完全未知、用户无感的状态"——按风险分三级，**三个等级就是审批目录里的三个子文件夹**：

| 级别 | 动作 | 生效方式 |
|---|---|---|
| **低**：新建技能/脚本/参考条目 | 写进 `<审批目录>/低/` | **不生效**；用户在复盘页批准后才移进正式目录（`tools/`、`skills/`、`references/`） |
| **中**：修改已有工具/技能 | 写进 `<审批目录>/中/` | 生成 diff，用户看过才应用 |
| **高**：删除 · 改系统提示词 · 改 App 代码 · 动用户文件 | 写进 `<审批目录>/高/` | **App 不做任何改动**，只能标记「已采纳」，用户自己动手 |

三条硬规则（2026-09-25 大收缩后）：

1. **它只有文本生成，没有任何工具调用**——原设想给它工具让它"测试"，实测推演的结果是：一测试就可能出问题，而且封闭环境里测试 = 又一个穷版主循环（冗余）。最终给它**且只给两个工具**：**AnySearch**（互联网搜索，本机已装：`.../Skill/Search/anysearch/scripts/anysearch_cli.js`）+ **写入**（范围锁死）
2. **写入范围 = 用户提供的某一个子文件夹，不是根文件夹**——子文件夹里按优化方向/任务类型建子目录（脚本 / MCP / 技能 / 待定），内容都是"提前写好"的建议。**历史对话只能看不能改**（可按类型、按时间翻），对自己的产出只能编辑，对其他一切文件夹零写入
3. **对当前 agent 零修改**——所有产出都是建议：脚本是"提前写好待用的"，MCP/技能是"建议添加的"，采纳一律走用户批准（批准后由 App 把文件移进正式目录，复盘 agent 自己永远不做这件事）。**拒绝 = 移到 `已拒绝/`，不是删除**

定位变化一句话：**复盘是链条最末端的兜底**——纯视觉/混合执行任务结束后打标记计数，Claude Code 升级任务结束后其记录也作为素材；它是"学习层"，不是"执行层"。

## 十一、成本与安全边界

| 边界 | 做法 |
|---|---|
| 一轮 token 上限 | 超了就停，水位不推进（下次接着看） |
| 读什么 | 只读 turn 记录与自己的运行记录 |
| 写什么 | 只写 `skills/`、`tools/_pending/`、`references/_pending/` |
| 不碰用户文件 | 不需要文件授权清单（它读写的是 App 自己的目录） |
| 不改代码 | 它写脚本，**不写 Swift**；想改 App 行为只能"建议" |
| 可观测 | 每次运行写一条用户可见的运行记录——**不做无感的事** |

## 十二、验收

| # | 判据 |
|---|---|
| R1 | **不重复**：连跑两次，第二次报告「看了 0 轮」 |
| R2 | **水位**：1 点那批处理完后，7–9 点新增的只在下次处理 |
| R3 | **冷却**：正在进行的会话的 turn 不进复盘 |
| R4 | **崩中断**：批量中途崩 → 重启后不重复（已打 `reviewedAt` 的跳过）也不漏（未打的仍在队列） |
| R5 | **待审不生效**：待审区里的东西**没有进入运行时**（`tools/`/`skills/` 正式目录无新增），批准后才出现 |
| R6 | **删除被拒**：让复盘 agent 尝试删一个已有工具 → 被拒并记日志 |
| R7 | **标签**：一轮对话产生的 turn 带 1–3 个**词表内**标签；模型没打标签时不阻塞（走聚类退化路径） |
| R8 | **模型测试**：填错 key → 测试按钮显示服务商错误原文；填对 → 绿 + 对勾 |
| R9 | 未配置模型时，功能**自动停用并说明原因**（不是静静地什么都不做） |
| R10 | 运行记录可见：设置页能查到上次跑了什么、看了多少、产出多少 |
| R11 | **token 上限**生效：构造一批超限的 turn，运行在预算处停下且水位只推到已完成处 |
