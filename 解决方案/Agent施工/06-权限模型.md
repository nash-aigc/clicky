# 06 · 权限模型

> 三个 sub agent 的权限各不相同，这是设计的一部分（不是事后补的安全措施）。
> 而它们的共同地基是**逐路径白名单**——那份文档设计已定、**尚未实施**，是本架构的前置依赖。
> 定稿 2026-09-25。

---

## 一、三个 sub agent 的权限分级

| | 图形 agent | 执行 agent | 文本 agent |
|---|---|---|---|
| 读文件 | ✅ 仅图形相关 | ✅ 按授权路径 | ✅ 按授权路径（只读） |
| 写文件 | ✅ **仅图形相关** | ✅ 按授权路径 | ❌ **完全不写** |
| 点击/打字/按键 | ❌ | ✅ | ❌ |
| 跑脚本 / MCP | ❌ | ✅ | ❌ |
| 在屏幕上显示 | 产出图形数据（**显示由 App 做**） | 可以（气泡/通知） | 可以（文字） |

**设计意图**：权限不只是安全边界，也是**能力边界**——工具少的 agent 更不容易跑偏，
所以"文本 agent 一个工具都不给"同时是质量控制手段。

## 二、地基：逐路径白名单（读/写分开）

来自 [`细节/02-文件访问授权.md`](细节/02-文件访问授权.md)（原文更细，这里是要点）：

| 要点 | 内容 |
|---|---|
| 模型 | **只允许用户显式加入列表的路径**；每条路径各有「读」「写」两个开关，**互不蕴含** |
| 空列表 | = 文件能力**全关**（不是默认给桌面） |
| 嵌套 | 取最长匹配：`/项目A` 只读 + `/项目A/notes.md` 可写 → 写 notes.md 通过 |
| 四条逃逸防线 | `../` 越级 · 符号链接（realpath 之后才比对）· 路径分量边界（`/A` 不匹配 `/Ab`）· 只接受绝对路径 |
| 写 = 创建/覆盖/追加 | **不含删除**；要删就单开工具与授权位 |
| 拒绝要说理由 | 模型拿到"哪条路径、当前允许什么"，避免反复试同一个路径 |
| 存储 | `AppSettings.json`（0600），与其他设置同一个文件 |

## 三、与现有两道闸门的关系

| 闸门 | 管什么 | 今天 |
|---|---|---|
| 「允许 Clicky 操作电脑」 | 点击 / 滚动 / 打开 | 已有 |
| 「允许打字和按快捷键」 | 打字 / 按键 | 已有 |
| **文件访问清单**（本模型） | 读写哪些路径 | **待实施** |
| 「允许调用工具库」 | 跑预先写好的脚本 | 设计已定（[`细节/06`](细节/06-工具库与MCP.md) §九） |

**四道闸门互相独立**：可以"允许点击但禁止碰文件"，也可以反过来。

## 四、一条必须由用户明确选择的例外

执行 agent 的**全盘读写**是这套体系里权限最大的一环。规则：

- **默认不给**
- 用户若要，必须是**单独一次、明确的**选择（不是某个总开关的副产品）
- 打开之后仍受"写不含删除"与四条逃逸防线的约束

## 五、Key 与秘密

| 规则 | 内容 |
|---|---|
| 密钥位置 | `~/Library/Application Support/Clicky/` 下的 0600 文件（`ToolSecrets.json` 等） |
| 绝不进仓库 | 仓库里 grep 不到任何 `sk-`（这是一条可自动校验的验收项） |
| 绝不回显 | 任何脚本的 stdout 都不打印 token（stdout 会进模型上下文） |

## 六、验收

| # | 判据 |
|---|---|
| P1 | 空列表 → 任何文件读写都被拒，且拒绝理由具体（哪条路径、当前允许什么） |
| P2 | 嵌套取最长匹配生效（构造 `/A` 只读 + `/A/b.md` 可写） |
| P3 | 四条逃逸防线各构造一次：`../`、符号链接、`/A` vs `/Ab`、相对路径——全部被拒 |
| P4 | 文本 agent 尝试写文件 → 被拒（它根本没有写权限） |
| P5 | 图形 agent 尝试写非图形文件 → 被拒 |
| P6 | 写操作不包含删除；删除工具不存在时无法删除任何东西 |
| P7 | 仓库内 `grep -rE "secret\|token\|sk-" tools/` 为空 |
