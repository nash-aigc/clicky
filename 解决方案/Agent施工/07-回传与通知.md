# 07 · 回传与通知

> 两件事：**结果怎么回到主循环**（已经存在，不用新造），以及**怎么让用户知道做完了**
> （鼠标旁一个对号 + 一句摘要，2–3 秒）。定稿 2026-09-25。

---

## 一、结果怎么回主循环（今天已有）

```
sub agent 执行完
   ↓ 结果写进数据块
主 agent 循环的下一轮读到它（pendingAccessibilityContext：CompanionManager.swift:2718 / 2749 / 2774）
   ↓ 主 agent 判断：
   ├─ 完成           → 总结成给用户看的话（→ §三）
   ├─ 未完成可补救     → 继续循环（上限 15 步）
   └─ 失败           → 换做法，或升级 Claude Code
```

今天这个通道里已经在装 `<screen_contents>`（屏幕结构摘要）与 `<agent_dispatch_results>`（派发结果）。
**三个 sub agent 的结果用同一个通道**——不需要发明新机制。

**传进去的是"数据"，不是"指令"**：数据块要明确标注是"屏幕/结果内容"，
不能让模型把里面的文字当作用户的吩咐（这是已有的安全设计，沿用）。

## 二、三态结果协议（决定要不要回传）

| 状态 | 谁定 | 主 agent 怎么处置 |
|---|---|---|
| `done_verified` | 脚本自己读回验证过 | 直接播报完成，**不绕回循环** |
| `done_unverified` | 说成功但无法自证 | **主 agent 自己决定**要不要多看一眼（大多数接受） |
| `failed` | 失败 | **必须回传**，带错误原文 |

**为什么这样分**：高频、便宜的那条路（脚本成功）保持零额外往返；
"出事了"的那条路一定有人接。

## 三、怎么告诉用户：对号 + 摘要（用户的设计）

用户的原话：

> 如果所有任务都执行完成，就返回任务完成，但**用户并不知道**，因此可以调用鼠标或坐标工具，
> 在鼠标右侧显示一个对话，比如显示一个**对号**，持续**两到三秒**。
> 这时可以不调用语音模型播放，直接在文字上显示；也可以调用语音模型播放。
>
> 大模型可以根据任务内容做通知：……生成"**任务完成**""**任务失败**""**任务进行中**"等词，
> 停顿一下，再说"**关于什么什么**"，这部分由大模型根据任务内容总结生成。
> 比如任务内容有 400 个字，大模型总结出更适合播报和通知的内容。

| 元素 | 用什么做 | 今天的状态 |
|---|---|---|
| 对号 / 图形 | `ScreenAnnotationManager`（已能画圈、箭头、线、曲线、多边形 + 标签胶囊） | **已有能力，接线即可** |
| 文字（"任务完成 · 关于…"） | 光标旁的气泡（`OverlayWindow`） | **已有** |
| 停 2–3 秒后消失 | 现有的自动消失机制（改时长） | **已有机制** |
| 摘要文字 | **主 agent 同一轮回复里生成** | 不需要额外调用 |
| 语音（可选） | 现有 TTS；不播报就是不调它 | **已有** |

**所以这一节基本是"接线"，不是"造轮子"。**

## 四、什么时候通知、什么时候不通知

| 情况 | 通不通知 | 形式 |
|---|---|---|
| 用户当场看着它做完（一次问答） | **不通知**（答案本身就是结果） | — |
| 多步任务做完 | ✅ | 对号 + 一句摘要（2–3 秒） |
| 后台/长时间任务完成 | ✅ | 对号 + 摘要 +（可选）语音 |
| **失败**（三级兜底全用完） | ✅ **必须** | 明确说明"这件事我没做成" + 原因一句话 |
| 还在进行中 | 可选 | "任务进行中"（长时间任务才需要） |

## 五、兜底链的最后一环：不许死循环

```
sub agent 自己重试（≤15 步）
   ↓ 仍不成
Claude Code（10 轮）
   ↓ 仍不成
通知用户「这件事我没做成」+ 原因   ← 到此为止，绝不再自动重试
```
