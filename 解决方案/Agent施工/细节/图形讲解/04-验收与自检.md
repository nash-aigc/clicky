# 04 · 验收与自检——怎么判断「真的完整实现了」

> 这份文档回答：**功能做完了没有？** 不是「跑起来看着像」，而是**每条需求都有一个可观测的判据**。
> 原则：任何一条需求，如果**说不出怎么观测它**，就等于没实现。所以下面每一条都带「看什么 / 期望值 / 看不到说明什么」。

---

## 一、什么叫「完整实现」——三层判定

| 层 | 判定 | 缺了它的症状 |
|---|---|---|
| **L1 跑通** | 全链路无错，图能画、能讲、能停 | 转圈后什么都没有 / 报错 |
| **L2 正确** | 每一步画的与讲的**对得上**，图元**零丢失**，位置对 | 「讲第一句时画的是第三步的东西」/ 图缺了直角标记 |
| **L3 稳定** | 打断、多屏、睡眠、连续使用都不崩不残留不泄漏 | 用十几次后风扇狂转 / 拔显示器后图留在不存在的屏幕上 |

**只有三层都过才算完整实现。** L2 是最容易「看起来成了其实没成」的一层——因为**错位是静默的**（画得出来、讲得出来，只是对不上）。

---

## 二、L0 静态自检（启动时或首次使用时跑，缺什么报什么）

| 检查项 | 判据 | 失败时的用户可见行为 |
|---|---|---|
| `figure_agent.py` 存在 | 文件可读 | 「画图助手脚本缺失：<绝对路径>」 |
| `python3` 可执行 | `FileManager.isExecutableFile` | 「python3 缺失：/usr/bin/python3」 |
| `node` 可执行 | 同上 | 「node 缺失（几何编译器需要）：/opt/homebrew/bin/node」 |
| DeepSeek key 可读 | 文件可读且非空 | 「画图助手的模型 key 缺失」 |
| geometry-dsl CLI 产物存在 | `dist/cli.js` 可读 | 「几何编译器未构建」 |
| 渲染器依赖的图元类型齐全 | 解析器分派表覆盖 `figure.json` 里出现的所有 `type` | **「遇到未知图元类型：Mark/kind=angle」并降级为整图淡入**（不许静默丢图元） |

最后一条是关键：**未知图元必须报出来并降级，不能静默不画。**

## 三、L1 契约与单元测试

| # | 测试 | 内容 | 判据 |
|---|---|---|---|
| T1 | **提取无丢失** | 对固定 `.geom` 集（triangle / incircle / pythagoras / 一个真实产物）渲染，比对 `figure.json` 的元素 id 集合与 SVG 里 `data-object-id` 的集合 | 两集合**完全相等**（双向：不多不少） |
| T1b | **golden 快照（独立口径）** | 同一组 fixture 的 `figure.json` 存成 golden 文件，**由人审核过一次** | 任何改动导致差异 → 测试红。**这是独立于提取器的口径**——T1 只能证明"提取器没丢东西"，T1b 才能证明"图本身还是那张图" |
| T2 | **SVG 契约快照** | 固定 `.geom` → 断言图元 `(id, type, kind)` 序列 | 上游 geometry-dsl 改契约 → 测试**变红**，而不是静默画错 |
| T3 | `M/L/A/Z` 解析 | 每种命令各一条路径，断言解析出的点数与端点坐标 | 端点误差 0 |
| T4 | **多子路径拆分** | 直角标记（两段 `M`）→ 断言拆出 2 个子路径且**不产生连接线** | 子路径数 == `M` 的个数 |
| T5 | **揭示并集算法** | 给定 `steps=[{ids:[3]},{ids:[4]},{ids:[7,11]}]`，断言第 k 步可见集合 | 与手算一致；**且能处理「同一 id 出现两次」**（先描边后填充） |
| T6 | 零元素步骤校验 | 构造一个「某步 ids 全是被隐藏的辅助线」的清单 | **被并入下一步**并记一条日志，而不是画一步空 |
| T7 | 时间预算 | 8 步 × 25 字 → 断言预估总时长 ≤ 上限 | 超限时**砍步数**并记日志 |
| T8 | 标签白名单 | 断言 `[SVG_TRACE:…]` 既被解析、又在 `streamingTagKeywords` 里 | 缺失 → 测试红（防「TTS 念标签」回归） |
| T9 | **渲染一致性（像素比对，最重要的一条）** | 把「渲染器全部揭示完成、动画进度 1」的画面与「用 `NSImage` 光栅化同一份 `.svg`」（现有 `show()` 那条路）逐像素比对 | 差异在抗锯齿容差内。**这条能抓到日志抓不到的东西**：丢图元、坐标偏移、子路径画错、Region 裁形错、样式缺失 |
| T10 | 未知图元降级 | 构造含未知 `type` 与含 `transform` 的 fixture | **必须报进 `unsupported` 并降级为整图淡入**，不许静默跳过 |

## 四、L2 可观测信号（每条都要真的打日志）

**判定原则**：下面每一条如果**在日志里看不到**，就说明那个环节没实现——不需要靠肉眼判断。

### 生成阶段

| 信号 | 期望 | 看不到说明 |
|---|---|---|
| `🖼 figure agent start: <task 前 40 字>` | 每次画图 1 条 | 标签没解析到 / 没进生成 |
| `🖼 figure agent done: <svg 路径> elapsed=12.3s retries=1` | 1 条，含**耗时与校验重试次数** | 生成成功但没记录耗时（无法定位慢在哪） |
| `🖼 figure.json elements=8 steps=6` | **元素数、步数** | 数据面没接上 |
| `🖼 figure anchor: label=三角形 frame=(…) source=AX` 或 `source=fallback-center` | 必须写清**来源** | 锚点在撒谎（见 [02 文档](02-数据面与渲染面.md) 第五节） |

### 演示阶段（关键：这条能直接暴露错位）

| 信号 | 期望 | 看不到说明 |
|---|---|---|
| `🎬 narration synth: 6 segments, first ready in 0.9s` | 1 条 | 并发合成没做（回到逐步 await 就会卡） |
| `🎬 step 3/6 reveal ids=[7,11] drawMs=420` | **每步一条，含 ids 与描边耗时** | 分步没发生（整块蹦出） |
| `🎬 step 3/6 speak start: 先画出底边 AB` | 每步一条，**打印讲解词** | 讲解没接上 |
| `🎬 step 3/6 speak done gapMs=0` | 每步一条，**gap 应为 0** | gap > 500ms 说明并发没生效 |
| `🎬 reveal finished: 6/6 steps, held 9.2s, fading` | 1 条 | 淡出没按预算算 |
| `🎬 narration cancelled at step 3/6 (reason: user-interrupt)` | 打断时 1 条 | 打断路径没接上（图会继续画） |

### 清屏与生命周期

| 信号 | 期望 | 看不到说明 |
|---|---|---|
| `🧹 board cleared: reason=<new-press \| interrupt \| new-question \| auto-fade>` | 每次清屏一条，**必须带原因** | 无法定位「图为什么不见了」 |
| `🧹 board kept during capture: step 2` | 循环截图时**不清** | 长动画被循环杀掉（老问题回归） |
| `🎬 narration registered in response task: yes` | 1 条 | 动画 Task 没归口 → 「停」停不掉 |

### 边界

| 信号 | 期望 |
|---|---|
| `🖼 figure cached hit: anchor=三角形 task=…` | 重复请求命中缓存（省一次生成） |
| `🖼 unknown element type: Angle — falling back to whole-figure fade` | 未知图元降级 |
| `🖼 screen params changed: reflowing board` | 显示器变化被处理 |

## 五、L3 端到端场景清单（手工验收，每场景一个判据）

| # | 场景 | 期望 | **判据**（不满足就是没实现） |
|---|---|---|---|
| E1 | 「照着屏幕上这个三角形讲一下」 | 图盖在原图上，逐笔画，每步一句讲解 | ① 三条边**分别出现**，不是整块蹦 ② 讲「底边」时底边在画 ③ 全部画完后图保持 ≥8 秒 |
| E2 | 普通提问「画个三角形」（不要求讲解） | 图贴元素右侧 | 静态或逐笔皆可，但**不要** 20 秒讲解；右侧放不下时翻到左侧 |
| E3 | 与屏幕无关「画个圆」 | 屏幕中央 | 不遮挡当前工作区 |
| E4 | 讲解中途说「停」 | 立刻停 | 图、声音、刘海状态**同时**归位；上下文收到 `interrupted` |
| E5 | 讲解中途说一句话（新问题） | 打断并进入新问题 | 旧图清掉、旧讲解停、新问题正常回答 |
| E6 | 讲完后追问「再讲一遍刚才那步」 | 模型知道刚才讲过什么 | 历史里有讲解内容（否则失忆） |
| E7 | 拔掉外接显示器 / 改分辨率 | 板子跟随或清掉 | **不留在不存在的屏幕上** |
| E8 | 关掉「允许屏幕图板」后再说「画个三角形」 | 不画，并说明已关闭 | 不是静默无视 |

## 六、L4 回归与稳定性

| # | 项 | 判据 |
|---|---|---|
| S1 | **连续画 20 次** | 进程数 / 内存**不随时间增长**（走 SwiftUI 路线应该平稳；若将来上 WebView，这条是硬门） |
| S2 | **产物目录** | 达到上限后自动清理，桌面不无限堆文件 |
| S3 | **上游契约变更** | 改 geometry-dsl 的 `data-*` → T2 变红（而不是画错图） |
| S4 | **时长上限** | 构造一个 20 步的图 → 被砍到上限并记日志；到总时长上限就收尾 |
| S5 | **锁屏/睡眠** | 睡眠时暂停；唤醒后当前步**从头续播**，不出现「声音在讲第三步、画面停在第一步」 |
| S6 | 打断后立刻再问同一个问题 | 不出现两块板叠加、不出现旧讲解的残余声音 |

## 七、判定树：症状 → 哪一层没实现

```
「什么都不出现」
  ├─ 日志没有 🖼 figure agent start   → 标签没解析（检查两处白名单 + system prompt）
  ├─ 有 start 没有 done               → 生成失败（看 retries / 超时 / 依赖自检）
  └─ 有 done 没有 🎬 step             → 演示没起（Task 没接进管线）

「图出来了，但整块蹦出来」
  └─ 有 🎬 reveal 但没有 🎬 step × N   → 分步没生效（并集算法没接上 / 步数被压成 1）

「讲的和画的对不上」
  └─ 有 step 日志但 ids 与讲解词不匹配 → 数据面没走「渲染后规划」（T1/T6 应该先红）

「第一步就卡住不动」
  └─ 🎬 narration synth 有但无 first ready → 首段合成失败（网络/key/额度）

「讲到一半没声了」
  └─ speak done 的 gapMs 很大           → 并发合成没生效（回到逐步 await）

「声音继续、画面停住」
  └─ 有 speak 系列日志但 step 卡住       → 时钟被外部环境接管（走回单一 Swift 时钟）

「说停了还在画」
  └─ 没有 narration cancelled 日志       → 动画 Task 没归口 currentResponseTask

「用久了变卡」
  └─ S1 失败                            → 资源泄漏（窗口/进程/任务未回收）
```

## 八、探针（照 [`../../开发经验/00-问题根因排查法.md`](../../../../开发经验/00-问题根因排查法.md) 的规矩）

**不要加日志，装仪器。** 四个可复用探针：

| 探针 | 装在哪 | 回答什么问题 |
|---|---|---|
| **阶段时间戳打点** | 生成任务与演示任务的首尾 + 每一步边界，同时打印「距起点」与「距上一步」+ 所在线程 | 「20–60 秒到底花在 DeepSeek、node 还是磁盘」——**必须带线程** |
| **RunLoop 跨度探针** | 演示步进的那个循环 | 「卡顿是主线程被占住还是被 await 挂住」——两者修法完全不同 |
| **渲染帧计数** | 描边动画期间 | 「逐笔是不是真的逐帧在画」——`TimelineView(.animation)` 没跑起来时画面是静态的，但日志看起来一切正常 |
| **无音频重放台（headless replay）** | 一个 DEBUG 入口：读固定 `figure.json` + 假播报（每步只 sleep 固定时长） | **把「讲的和画的对得上」变成可比对的时间线**，而不是靠人眼看。它 dump 出 `step k → ids / drawStart / drawEnd / speakStart`，可以直接与 `steps` 的期望顺序做断言 |

第四条是这一整套验收的支点：**E1 那条"讲底边时底边在画"的判据，有它才能自动化**（没有它就只能靠肉眼，而肉眼判断在本仓库已经被证明不可靠）。

**一条已踩过的读法教训**（写在这里防止重犯）：探针报告的是「刚刚结束的一段忙碌」，紧跟其后的日志是下一步工作，**不是原因**。用日志的相邻做归因等于倒因为果。

## 九、每阶段的验收 Gate

| 阶段 | Gate（不过不进下一阶段） |
|---|---|
| P0 数据面 | T1（零丢失）+ T6（零元素步骤）通过；生成的 `figure.json` 能用肉眼核对到「每个 id 对应图上哪一个图元」 |
| P1 契约测试 | T2 通过，且**故意改一次上游契约时它真的变红** |
| P2 渲染器 | E1 的前两个判据通过（三条边分别出现、讲与画同步） |
| P3 语音与管道 | E4/E5/E6 通过；日志里 `gapMs ≈ 0`；`narration cancelled` 能出现 |
| P4 收尾 | L0 自检六项全过；S1/S2/S3/S5 通过 |
| P5 可选 | 02 文档第七节的四项实测全过，且 SwiftUI 渲染器保留为降级路径 |
