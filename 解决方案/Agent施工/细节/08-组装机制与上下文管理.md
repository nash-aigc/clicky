# 08 · 组装机制与上下文管理

> 用户指认这是"真正的重点和核心"：
>
> > 关于 AI 如何自我总结、自我拼接或自我组装工具调用，这部分才是真正的重点和核心。

## 一、组装的原料清单——"AI 能做哪些事情"（这个清单本身就是给模型的）

| 原料 | 来源 | 调用形式 | 例 |
|---|---|---|---|
| 鼠标 / 键盘动作 | MacosUseSDK（进程内） | `[CLICK:x,y:label]` `[TYPE:]` `[SCROLL:]` `[DRAG:]` `[PRESS:]` `[SELECT:]` | 点"发送"按钮、输入搜索词 |
| 按区域截图 / OCR | 截图管线 + Vision | `[SCREENSHOT:区域]` `[OCR:区域]` | 截左侧 → 识别成文字 |
| 文件工具 | `FileManager` + 授权清单 | `[FILE_LIST]` `[FILE_READ]` `[FILE_WRITE]` | 存到桌面 |
| 模块化单步脚本 | 工具库（`tools/`，一个函数一个工具） | `[RUN:工具:参数]` | 备忘录新建、Notion 保存 |
| **MCP 工具**（运行时接入） | 已安装的 MCP 服务器 | `[MCP:服务器.工具:参数]` | Notion 官方工具、搜索 |
| 技能（方法论，不是动作） | `skills/`（热加载） | `[SKILL:技能名]` → 正文注入 | 「这类文章怎么写」 |
| **坐标吸附**（能力增强，非动作） | AX 树 | 自动——见 §六 | 按名字点，落在真实控件中心 |

**这份清单的注入方式是本设计的第一个关键决定**：它**不是**一段写死的提示词。提示词里只有四类规则和纪律（见 §五）；原料以 **L0 索引行**存在（每项一行：名字 + 何时用），**按需展开**。

## 二、MCP 运行时接入：能搭好，这样搭

| 项 | 设计 |
|---|---|
| 配置 | `~/Library/Application Support/Clicky/MCPServers.json`（0600）：服务器名 → 启动命令 / URL / 环境变量 |
| 生命周期 | 懒启动（第一次用到才拉起）、常驻复用、App 退出全量收尾 |
| 工具发现 | 连接后 `tools/list` **缓存一次**；`tools/list_changed` 通知才刷新 |
| **快路径 vs 组装路径** | **快路径（②）不碰 MCP**——它只走固化的脚本；**组装路径（③④）可以现场调 MCP 工具**（这正是 ③ 的定义） |
| 组装时怎么看见 MCP 工具 | **按分类注入**：组装上下文里 MCP 工具只出现"服务器.工具 + 一句话"，按服务器分组；模型点名某个工具时才展开它的完整参数 schema |
| 调用 | `[MCP:服务器.工具:参数]` → 运行时客户端（stdio JSON-RPC）→ 结果回填 |
| 失败 | 服务器没装/挂了 → 该服务器的工具**整体标为不可用**（不逐个试错）；调用超时/报错 → 如实回填 |

这就是之前"MCP 客户端"学习计划的落点，且与「MCP 装但不直灌」（[`06`](06-工具库与MCP.md) §八）完全一致：**MCP 的原始 schema 永远不进系统提示词**，组装上下文里的只是一行索引 + 按需展开。

## 三、技能：位置与加载的硬保证

**"会不会全量加载"必须从机制上排除，不靠自觉**：

| 项 | 决定 |
|---|---|
| 位置 | **`~/Desktop/clicky/skills/`**——与 `tools/` 并列、进仓库、可版本化；审批目录里批准的技能由运行时复制到这里 |
| 结构 | 每个技能一个 `.md`，front matter 携带 `name` / `description`（一句话，何时用）/ `keywords`；正文是方法论 |
| **L0 里是什么** | **只有 front matter 折出来的一行**：`技能：xxx — 何时用`。正文一个字都不在 |
| **正文何时加载** | 仅两个触发：模型写 `[SKILL:名字]`（主动调用）；复盘页/对话中命中关键词（参考条目同机制） |
| **硬预算（超了就拒绝加载，不是静默崩）** | L0 索引总量 ≤ 6 KB；单个技能正文 ≤ 4 KB；技能总数 ≤ 50——超限日志告警，L0 里最久未用的降级为"仅关键词触发" |
| 绝不全量加载 | 运行时**只读 front matter** 构建索引（启动时一次，文件变更时增量）；正文按需读盘 |

**验收里专门有一条**：装 60 个技能，测启动后每次请求的提示词体积——必须与装 10 个时同量级（只多 50 行索引），且**任何一个技能正文都不在**（日志可验证）。

## 四、组装的上下文管理：需要设计，规则如下

用户的前提：组装任务 10–30 轮，每轮都要交给模型，但**不能把历史原样重放**（"不要直接重复执行"）。项目里已有先例（对话的「历史自动压缩」，`compressedHistorySummary`），组装循环用同一思想但更简单：

| 层 | 内容 | 生命周期 |
|---|---|---|
| **任务卡（常驻，不变）** | 原始需求原文 + 用户补充 + 验收标准（"怎么算完成"） | 整个任务 |
| **进度摘要（滚动压缩）** | 每完成一步压成一行：`✓ 已打开 Chrome → ✓ 已新建标签页 → ✓ 已输入地址并回车` | 超过窗口就并进这行 |
| **近窗全量（最近 5 步）** | 最近 5 步的完整观察（模型对截图的读图摘要 + 动作结果一行） | 滚动 |
| **最新截图** | 当前这步的图 | 1 帧 |
| **失败步保留细节** | 失败的步骤**不压缩**（错误原文 + 当时截图的读图），直到任务结束 | 到收尾 |

| 规则 | 为什么 |
|---|---|
| 每步的"观察"是**模型自己对截图的一句话读图**，不是截图本身留档 | 截图只送最新一帧；历史以文字摘要存在——token 随轮次线性慢涨，不指数涨 |
| 压缩是**追加式**的：摘要只增不改 | 与导出水位的纪律一致；模型不会看到自相矛盾的历史 |
| 任务卡永不压缩 | 防止长任务后半程"忘了原始目标"（这是长循环最常见的失败） |
| 30 轮时的量级估算 | 任务卡 ~200 字 + 摘要 30 行 ~600 字 + 近窗 5 步 ~500 字 + 一张截图 ≈ 与单轮视觉请求同量级——**上下文不随轮数爆炸** |

## 五、哪些在提示词里，哪些是设计（直接回答"都写在提示词里吗"）

| 在**系统提示词**里（常驻） | 不在提示词里（**管线行为，按需注入**） |
|---|---|
| 四类执行策略与判据 | 工具 / MCP / 技能的 **L0 索引行**（超预算有降级） |
| 纪律：拒绝优于选错 · 一步一动作 · 10–30 轮上限 · 破坏性需明确要求 | 工具的**参数 schema**（`[RUN:]` 写错参数时随错误回填） |
| 组装原料的**存在性**（有哪些类别的能力，不列细节） | 技能**正文**（`[SKILL:]` 命中才注入） |
| 现写代码的边界（危险词即拒） | MCP 工具的**完整 schema**（点名才展开） |
| 任务卡（每次请求重建） | 进度摘要 / 近窗观察 / 失败细节（组装循环的滚动上下文） |

**判断标准一句话**：提示词放**规则和存在性**；一切**细节**（参数、正文、schema、历史）都是管线的按需注入。这条定了，几十个技能、几百个工具都不会崩——因为常驻部分有硬预算。

## 六、坐标吸附：你忘掉的那个东西（代码事实）

你记的是 **`accessibilityElementFrame(matchingLabel:nearestTo:)`**（`MacosUseController.swift`，经 `resolvedClickPoint` 调用）：

- 模型点击时给的是**元素的名字**（label），代码拿名字去**最前台应用的 AX 树**里查这个元素的真实 frame，**命中就把点击吸附到控件中心**——模型自己的坐标只是兜底（实测误差可达 ±25% 屏幕宽）
- 同一条链服务三个调用方：**点击**（`:750`）、**光标飞行**（`resolvedPointerLocation`，`:820`）、**图形吸附**（`annotationEnclosingFrame`，`:1011`）
- 实测战绩：Calculator 的「7」键，名字命中后落到精确的中心点（`(964,722,48,48)`），5/5 点中

**对组装的意义**：这是组装可靠性的最大杠杆——模型负责"点哪个（名字）"，代码保证"点得准（真实坐标）"。技能和复盘产出里凡是点击步骤都**必须带元素名**，这条要写进技能模板。

## 七、复盘确认（已调整到位）

三个关注清单在 [`../复盘Agent/README.md`](../复盘Agent/README.md) §七：**A 高频纯代码**（→ 进预设表，第 0/1 步命中率↑）、**B 高频组装**（→ 沉淀技能或脚本组合）、**C 反复失败/用户引导型**（→ 重点对象，把引导写成方法论）。v2 框架下它们的产出正好是迁移通道：③→④（技能）、④→②（提炼）。

## 八、验收

| # | 判据 |
|---|---|
| A1 | 装 60 个技能 → 每次请求提示词体积与 10 个时同量级；**无任何技能正文**在提示词里（日志验证） |
| A2 | `[SKILL:名字]` 命中 → 该技能正文出现在当轮上下文，**且仅当轮** |
| A3 | 技能正文 > 4 KB → 拒绝加载并告警（不是截断后静默使用） |
| A4 | MCP 服务器未装 → 组装上下文里该组工具标"不可用"；装上后（list_changed）自动出现 |
| A5 | 组装 30 轮的任务 → 上下文体积曲线平缓（任务卡+摘要+近窗，与单轮同量级）；**第 30 轮模型仍能复述原始目标**（任务卡未压缩） |
| A6 | 失败步的细节保留到收尾（中间轮次模型仍能看到错误原文） |
| A7 | 按名字点击 → 日志可见 AX 吸附命中（`resolvedClickPoint` 路径）；未命中 → 落在模型坐标并注明 |
| A8 | 每步观察是一句话读图（日志），不是截图重放 |
