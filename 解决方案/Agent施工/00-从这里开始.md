## 一、一页说清这套系统是什么

```
                          用户的一句话
                               │
                               ▼
                   ┌───────────────────────┐
                   │  高速通道（可选，快）    │  ← 复盘统计长出来的，≤20 行入口
                   │  命中 → 直接执行，不进循环 │     命中不了 / 失败 → 落回下面
                   └───────────┬───────────┘
                               ▼
        ┌──────────────────────────────────────────────┐
        │  主 agent（唯一的大脑）                        │
        │  提示词只有四样：屏幕 + 用户的话 + 历史 +        │
        │  「什么时候叫哪个 sub agent」的目录              │
        └───────┬───────────┬───────────┬──────────────┘
                ▼           ▼           ▼
          ┌─────────┐ ┌─────────┐ ┌─────────┐
          │ 图形 agent│ │ 执行 agent│ │ 文本 agent│
          │ 只碰图形文件│ │ 工具最多  │ │ 零工具、只读│
          └────┬────┘ └────┬────┘ └────┬────┘
               └───────────┴───────────┘
                           │ 结果回主循环做确认
                           ▼
        ┌──────────────────────────────────────────────┐
        │  主 agent 总结 → 用户听到语音 / 看到鼠标旁的    │
        │  对号 + 一句话（停 2–3 秒）                    │
        │  做不成：10 轮 → Claude Code → 再 10 轮 → 通知你│
        └──────────────────────────────────────────────┘
```

**一句话**：一个主 agent，三个各有权限的 sub agent，一个外援；标准路保证做对，高速路负责快。

## 四、关于 JEV（一句话，避免再起争论）

**现在不装 JEV。** 实测它是准的（三分类 19/19、四问 14/14、一次调用多题几乎不加价），
但它解决的是"**候选多到提示词装不下**"的问题，而那件事今天还没发生：

| 什么时候 | 决定 |
|---|---|
| 固化脚本 **< 150 条**（今天十几条） | 全部直接给主 agent 看，**不装任何中间层** |
| **> 150 条** | 升级闭集路由（本地短语表 + 目录门禁） |
| **数百条** | 才评估 JEV 这一类决策模型 |

依据与实测数据在 `细节/07-工具路由与instant-agent.md`，本节只是结论。
