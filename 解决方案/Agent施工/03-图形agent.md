# 03 · 图形 agent

> 负责"在屏幕上让你看到东西"：指位置、圈出、画框、画箭头、生成图形与图解。
> **它不改变机器的任何状态**——只让屏幕多出图形或指示。定稿 2026-09-25。

---

## 一、它干什么

| 需求 | 它做什么 | 产物 |
|---|---|---|
| "把那个按钮圈出来" | 画一个圈（或框）在目标位置 | `[SHAPE:circle:…]` |
| "指给我看发送按钮在哪" | 光标飞过去停在旁边 | `[POINT:x,y:lab​el]` |
| "画个图讲讲 TCP 三次握手" | 生成一张图解，逐笔画出 + 逐步讲解 | `[SVG_*]` |
| "在屏幕上标一下这里和那里" | 多个标注（上限 4 个） | 多条 `[SHAPE:…]` |

**判据**：完成之后**机器状态零变化**（App 没开关、文件没动、键没按）——变的只是屏幕上的画面。

## 二、权限

| 项 | 权限 |
|---|---|
| 图形相关文件的**读写** | ✅ 需要（生成 SVG 要写文件） |
| **其他任何文件** | ❌ **一律不可以** |
| 点击 / 打字 / 按键 | ❌ 不可以（那是执行 agent 的活） |
| 屏幕读取（截图） | ✅ 只读 |
| 在屏幕上显示 | **它不直接做**——见 §四 |

## 三、它的技能里放什么

今天写在主 agent 提示词里、要搬过来的是这三节（合计约 3,300 字符）：

- `element pointing:` — 怎么把位置表达成坐标、标签怎么写
- `drawing on screen:` + `kinds:` — 有哪些图形、各自怎么描点
- `the user can mark the screen themselves:` — 用户自己圈了区域时怎么办

**外加**它自己的做法：怎么算坐标（几何编译器）、怎么排版不重叠、怎么逐笔呈现（图形讲解的那套节奏）。

细节原文：[`细节/图形讲解/`](细节/图形讲解/)（数据面与渲染面、语音节拍与生命周期、验收与自检）。

## 四、边界：它产出图形，**显示由 App 做**

这条必须写清楚，否则会出现两份绘制逻辑：

```
图形 agent  →  产出"画什么"（形状、坐标、颜色、标签）
     ↓
App 的画布  →  真的画到屏幕上（ScreenAnnotationManager / FigureBoardController）
```

| 由 agent 做 | 由 App 做 |
|---|---|
| 决定画什么、画在哪、什么形状 | 建透明覆盖窗口、逐笔动画、自动淡出 |
| 生成 SVG 文件 | 把 SVG 显示在白板窗口里 |

**理由**：今天画绿圈、画白板这两件事已经由 App 做得很完整（含淡出、generation 防误杀），
让 agent 自己也去显示 = 同一套逻辑两份实现，以后必然漂移。

## 五、失败怎么办

| 失败 | 处置 |
|---|---|
| 定位不到目标（找不到元素） | 退化成一句文字说明（"我看到三个按钮，你要的是哪一个？"） |
| 画图失败（校验没通过） | 画图工作流内部自动重试 ≤3 轮；仍失败 → 一句文字说明 |
| 用户中途换话题 | 立即停止绘制并清掉已画的（今天的机制照旧） |

**没有 Claude Code 兜底**：画不出来只是一句说明，不值得升级外援。
